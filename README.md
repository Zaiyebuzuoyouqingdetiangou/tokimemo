# 心跳回忆

## r49.0：深度修复 · 跨聊天档案生成

- **已有档案可以在后台继续生成。** 从档案室明确选择 A 后会冻结 A 的角色、聊天、档案版本与允许上下文；切到 B 聊天不会取消 A，也不会让 A 读取或写入 B。A 被更新、重建、删除或启动同模式新任务时，旧结果自动失效。
- **TT 派生内容保全链重新收口。** 内存、压缩 metadata、本机备份和待提交记录继续按同一角色 / 聊天 / `archiveRevision`、生命周期与删除栅栏校验；ArchiveTarget 在每个异步边界沿用发起时的生命周期，扩展销毁后的迟到读取、请求和写入都会被拒绝。
- **Connection Profile 与手动 API 严格隔离。** “1.1.18 一键配置”和“手动配置”保持同级醒目；B 拉模型失败只保留 B 自己已存模型，手动线路也只使用手动配置。Heartbeat 可控错误统一脱敏。
- **第三方读取只走登记的公开接口。** r49 退役了直接读取 EverMind 私有 settings / metadata / API Key 的旧自动适配，也移除了按全局函数名、任意 `extensionPrompts` 或 `chatMetadata` 字段猜记忆来源的启发式 reader；已经确认进 Heartbeat 来源账本的资料仍可读，其他用户可继续用显式文件导入。柏宝书只走公开 API v1，矛盾的完整度/总数声明会降级为部分读取而不能替换旧完整基线。
- **一个受控 World Presentation 服务全部表现层。** 出行、房间、背影小人、宠物、私人终端和节日贺卡共享同一证据决策；角色卡 / 当前世界书优先，精确复核的 Character Profile 次之，再到两段不重叠正式档案共识，证据不足保持中性。电影、梦境、虚构和否定描述不能洗成世界事实。
- **日历与检索继续保持安静。** 日历只有角色写下的 memo、待办、备注、随笔和安全节日贺卡；标签支持多选、清除和状态保持。旧 Calendar、Phone、Travel 数据原样迁移或明确降级，不伪造缺失证据。
- **缓存里的表现 token 也要重新过白名单。** Travel 的 tone / mapTheme 与 Calendar 状态圆点在最终渲染前再验证；房间的当下生活与共同往事分开。“今天/现在”不会放行夹带的过去叙述，整段必须逐分句证明为当前态；共同过去只有 exact Mxxx 且可见文字包含真实锚点时才显示。
- **反查用户私人终端未硬做。** 当前证据结构无法稳定区分可展示的用户自述与不应推断的私人事实，r49 选择安全阻断。

## r48.0：两个人的日历 · 世界观节日贺卡

- **只在世界观中明确存在的节日出现。** 节日来自受控角色卡 / 世界书 / Persona 固定日期；没有可靠节日就不出卡，不为了功能凭空造节日。
- **不是固定贺卡模板。** 模型只给受限 art direction，本地 renderer 用安全 SVG primitive、HTML 与 CSS 重新构图；文字、图画、书写、图文、极简表达同级，正文和落款都可为空。
- **表现跟世界观走。** 贺卡可以使用受控的 card / paper / letter / scroll / folio / screen 载体；具体内容继续结合 {{char}} 人设、节日与当前 archive 关系状态，不建立“某性格=某形式”的固定映射。
- **不伪造历史。** 贺卡属于 Calendar Derived Content，不写回 Mxxx；世界观有某个节日不等于两个人过去一起过过该节日。
- **Calendar v6 安全迁移。** r47/v5 逐日内容继续保留；日期格只显示低干扰贺卡标记，选中日期后显示成品，不堆玩法注释。

## r47.0：TT 持久化增强 / 世界观表现 / Heartbeat 独立主题

- **派生内容优先完成持久写回。** 生成成功后会在显示完成前尝试把当前派生缓存压缩、写入同档案独立备份并提交 metadata；无法安全提交时继续使用已有待写回机制。完整 runtime 打开档案时，同一 `archiveRevision` 下如果本机备份比聊天缓存更新，会恢复较新的派生缓存；普通酒馆启动仍不会为此打开 IndexedDB。
- **错误正文不再由 Heartbeat 直接回显。** HTML/Cloudflare 等上游页面只显示状态与安全分类，API Key、Authorization、Prompt、聊天、档案和响应正文继续禁止进入 Heartbeat toast/日志。宿主 SillyTavern 自己产生的后端 toast 不在插件控制范围内。
- **出行、房间与私人终端更贴世界观。** 远方纪念载体新增书信、手札、卷轴、任务记录、数据记录等受控类型并兼容旧明信片；房间不再把帽子当默认人设推导；私人终端增加低技术与特殊世界观载体，并按 App 类型使用不同的本地信息结构。模型仍不能提供可执行 HTML/CSS/JS、任意 URL、class 或坐标。
- **档案标题更短。** 新生成标题要求 4～14 个汉字、像私人回忆册章节名；旧档案不会被自动改名。
- **新增 Heartbeat 独立主题。** 默认配色固定为珍珠白、雾蓝灰与低饱和粉紫/青绿；可选跟随宿主基础前景/背景或自定义调色盘。卡片透明度只改变卡片表面，不会连文字一起变淡；主文字和次文字会同时对不透明及合成后的卡片背景做 4.5:1 对比度保护。关键背景、文字、按钮、输入框和横排布局使用插件自身作用域，避免被普通宿主美化 CSS 覆盖到不可读。跟随模式只读取浏览器标准计算样式，不调用第三方美化插件私有设置或接口。
- **继续精简界面说明。** 功能页不堆玩法注释，只保留必要标题、状态、安全确认和短操作提示。
- **本版没有用删校验的方式实现跨聊天后台生成。** “聊 B、为已存档 A 生成”、反查终端和兔子镜标签过滤仍留给后续基于明确世界线/隐私边界的审查，不在 r47.0 中硬接。

## r46.0：通用记忆接入 / 来源存档 / 生成结果保全

> 历史说明：本节记录 r46 当时的行为；其中 EverMind 私有配置自动适配与任意全局 reader 已在 r49.0 退役。

- **常用来源自动读取。** 通过带版本和能力声明的只读适配器识别酒馆 `1_memory`、柏宝书公开 API v1 与 EverMind；来源会绑定当前角色和聊天，并显示完整、部分、截断或失败状态。实验性的任意全局 reader 仍默认关闭，不把“碰巧读到”宣传为完整适配。
- **未知插件可以显式导入。** 设置页提供醒目的“自动读取”和“导入记忆”，支持本地 JSON、JSONL、TXT 与 Markdown；导入前先显示角色/聊天归属、内容样例、条数与字符数，并要求明确勾选“这是已经发生的历史/摘要，不是角色设定”，确认后才绑定当前聊天。未知 JSON 的非元数据字符串叶也会带字段路径进入预览；API Key、密码、Token 和连接配置会被排除并标为“部分读取”，既不会藏在预览后面，也不会进入账本或模型。确认文件只导入该文件，不会顺带扫描其他插件。外部文字只作为资料解析，不执行其中的 HTML、脚本、宏或提示指令。
- **心跳回忆拥有独立来源账本。** 导入原文分片、稳定来源 ID、版本、覆盖信息与内容散列写入本机 IndexedDB；生成预算与完整来源存储分开。技术来源 ID 由完整 provider 身份生成，超长且前缀相同的文件名不会互相覆盖。对方插件卸载或停止注入后，已导入资料仍能从本机账本回读；用户可单独清除当前聊天来源，不影响酒馆聊天、第三方记忆或正式 Mxxx。
- **世界书用途不再混淆。** 默认仍把所选世界书当作设定解释；只有用户明确标记为“历史摘要来源”的条目才可作为摘要级历史证据，并保留世界书和条目锚点。历史来源按书独立保存；旧版合并来源会原子迁移，精确取消某个 UID 会立即生效，即使下一次读取暂时失败也不会把已取消条目重新送入生成。
- **修复记忆静默丢料。** 外部记忆真正获得预留空间；长摘要按片段保存，不再悄悄截成 6000 字；provider 原始记录 ID、revision 和 coverage 会被保留。没有正文但已有明确绑定历史来源时也可以建档。
- **生成切聊与刷新更安全。** 当前聊天离开确认与全网页未保全工作分开判定；CG、今日生活不再错误锁住别的聊天。原生确认框在移动 WebView 中不可用时会放行宿主切换/关闭，不再把窗口锁死。已经完成但尚未写回原聊天的结果会进入浏览器本地的有界待提交记录（最多 24 项、3.5 MB、7 天），回到原聊天后再按原角色/聊天/档案版本写回。备份或缓存等待结束后会再次核对角色；完全克隆、同名或同头像角色也按角色卡槽隔离，同毫秒产生的新结果不会被旧 ACK 误删。页面卸载会覆盖全部仍在飞行或未保全的工作。
- **远方明信片按地点绘景。** 每个地点使用白名单风景类型；旧数据会从地点名称、区域和简介安全推断。海港与雪山不再因为共用地图主题而画成同一种景色，桌面和移动端构图也不再裁掉关键海面或地面。

## r45.0：独立 API 双配置 / 连接稳定性修复

- **两个入口同级醒目。** 设置页直接显示“1.1.18 一键配置”和“手动配置”两张心跳回忆粉蓝卡片，只保留短状态、必要字段和模型按钮，不照搬兔子镜 UI。
- **一键配置先验能力。** 配置写入、模型刷新和正式生成前都会检查 Connection Profile 的 Secret 转发与请求级模型覆盖能力；能力不完整时在付费请求前停止。入口与错误提示统一标注 `1.1.18`。
- **手动 OpenAI 兼容通道。** 可填写 Base URL、API Key 与模型 ID，也可显式拉取模型；浏览器始终只请求 SillyTavern 固定同源 `/status` / `/generate`，不会直接跨域访问第三方 URL。带 Key 的远端地址要求 HTTPS，本机 loopback 开发地址仍可使用 HTTP。

- **配置竞态关闭。** 一键配置、模型列表和生成结果都绑定配置 epoch / 去敏指纹；等待时切换来源、修改模型或停用 runtime，迟到结果不会覆盖新设置或写入缓存。

## r44.0：感情扫描共同回忆 / 独立出行地图 / 背影房间与告白彩蛋

- **人际庭园增加 NPC 视角。** 点击非用户 NPC 头像后会显示该 NPC 对 {{char}} 的视角；动态关系优先于固有设定，旧缓存缺少视角时明确提示刷新，不会冒充秘密或新增事实。
- **成就显示解锁条件。** 已解锁成就同时展示“如何解锁”和解锁时间；旧缓存安全回退到原证据锚点或说明。
- **新增档案室独立“他的出行路线”。** 它不是手机 App：近地图地点点击后播放 {{char}} 的逐句对白，远地图地点打开完全由本地 CSS 与文字构成的明信片。私人终端会过滤地图、导航、路线、出行与交通类 App。
- **告白回看加入本地心跳彩蛋。** 弹窗提供触碰心跳、悬停核心、解锁短句、暂停/恢复日志、稳定信号等交互，并实时更新视觉、日志与诗句。模型只返回经清洗的结构化文字，不能提供或执行 JavaScript、HTML、CSS、URL 或事件处理器。
- **旧档案保留，必要时显式补全。** 旧房间会显示“补全宠物与视觉设定”，即使没有新 Mxxx 也可扫描人设/世界书，不删除旧物件或深层内容。如需用新差异校验完整重做旧房间，使用顶部管理器的“重新生成整个分类”，并注意确认框中的依赖内容重建提示。旧 CG 台词可用单张重生成升级感情扫描。
- **历史身份与异步导航保护。** 相簿、人际庭园和明信片不会借用另一聊天的角色/用户；手动分类即时刷新身份缓存。地图标记不重叠，切换页面/聊天时相簿延迟和 Ending 彩蛋会安全收束。

## r43.0：人设化房间与终端 / Calendar v5 逐日手账 / 蝴蝶内容强化

- **两个人的日历升级为 Calendar v5 逐日页。** 每个具体日期、无年份纪念日和待定约定都有独立页面；草稿、便签、特别备注、页角随笔与手动 To-Do 只属于当前页，不再由所有日期共用。没有剧情事项的空白日期也可以点开并使用自己的页面；长期积累超过 480 个页面也不会被迁移逻辑静默截断。

- **房间和房中人物按人设变化。** 世界书/角色设定中有明确线索时优先采用；缺少明确描述时再根据人物时代、身份、职业、生活方式与气质选择代码内置的安全房型、配色、陈设及 CSS 人物轮廓和脸型比例。明确设定字段与人设推导字段分开，模型照抄合法示例也不会让全员变成同一套造型。房中人物不套用档案头像，也不接受模型提供的 CSS、HTML、URL 或坐标。
- **私人终端恢复完整设备层级。** 先看到有状态栏、壁纸和 App 图标的设备主页，点 App 进入独立列表，再点条目进入详情；设备类型、主题配色、图标风格、App 组合和排序会随人物与世界观变化。手机、腕式设备、终端和传讯器使用各自形态，不复制真实商业产品界面。
- **蝴蝶效应只强化内容，不重做 UI。** 原有分歧树、配色、观测页、SIGNAL 动画与观测点 Ω 保持原状；生成会读取角色卡、User Persona 与相关世界书，至少给出 8 个实质不同的平行人生。本地在保存前检查第一人称长独白、现世回应、冷静的 SYSTEM NOTE、Ω 终局以及第三方恋爱禁令，不合格结果不会覆盖旧内容。

## r42.5：独立档案备份 / 超大缓存保护 / 版本 CAS

- 正式 Mxxx 档案与兼容的派生缓存会在用户显式加载完整 Heartbeat runtime、建档/更新或打开历史档案时，写入浏览器本机 IndexedDB 独立备份；不再只依赖源聊天 `chatMetadata`。
- 源聊天文件删除、丢失或无法读取时，档案室会尝试从独立备份恢复，并以“永久只读”方式显示。备份不会自动绑定到其他聊天；清除站点数据、换浏览器或换设备不会带走这份本机备份。
- 所有正式档案提交统一执行 `archiveRevision` compare-and-set。生成期间版本变化时，迟到的前台或后台结果会被丢弃，不会覆盖较新档案。
- 12 MB 上限统一按 UTF-8 字节执行到压缩、无压缩、延迟写回与销毁路径。候选缓存过大时保留上一份有效压缩/原始缓存，不再用不可读的超大 raw cache 覆盖它。
- 明确“双确认删除当前档案/角色档案”会一并删除对应 Heartbeat 本机备份内容，并留下不含档案内容的极小删除栅栏，阻止迟到的 seed/缓存任务把备份复活；“仅从档案室移除索引”仍不删除备份或源聊天数据。
- r42.0 轻量 bootstrap 不变：普通启动和零解压性能诊断都不会导入完整 runtime，也不会打开 IndexedDB。

## r42.4：性能诊断可收起

## r42.3：安全边界与长期状态收口

- EverMind 仅允许 HTTPS；HTTP 只对 URL 解析后确认的 loopback（`localhost`、`127.0.0.0/8`、`::1`）开放，不再把 Bearer API Key 发往远程明文地址。

- disable / clean 会清空 preflight、历史 snapshot、模型列表和档案一览等瞬时缓存，并用 runtime lifecycle epoch 阻止旧异步结果、正在 gzip 落盘或 gunzip hydrate 的 Promise 在销毁后回填。r46 起，已经完成且等待回到原聊天写回的 durable deferred commit 不再随 runtime 销毁清空。

## r36：两个人的日历

| 日历状态 | 含义 | 可信来源 |
|---|---|---|
| **已经度过** | 剧情里确实发生过、且档案记有明确日期的日子 | 本地直接读取正式 Mxxx；模型不能创建 past |
| **已约定 · 未发生** | 剧情中明确约好、但后续档案尚未记录兑现或取消的安排 | 必须回指真实 memory ID + anchor，通过 evidence 校验 |

- 世界设定只有出现明确 `MM/DD` 或 `YYYY/MM/DD` 才进入未来日历；「冬季祭典」但没有日期时不会猜。
- r36 **不提供“点未来节日自动生成特别篇”**。这是刻意保留的边界：先区分事实、约定和设定，后续再决定节日特别篇的玩法。
- Calendar 是独立 mode，不塞进 HEART；它保存于派生 cache，不改正式档案 schema。

## r30：所有内容都在原有基础上增量增加

先像以前一样点击“增量更新当前窗口档案”，让正式档案追加新的 Mxxx；然后在想扩充的内容入口点击“增量追加”。每一项都有自己的本地消费游标，只读取尚未用于该项的新 Mxxx。没有新记忆时会直接提示，不会调用模型，也不会把旧内容再讲一次。

| 内容 | r30 的追加行为 |
|---|---|
| 回忆相簿 | 追加新 CG 节点和共同回忆；旧描述、评论与已绘制图片保持不变 |
| ADV EVENT | 追加新事件索引；旧 CG 图片和已完成 ADV 全文保持不变 |

| ENDING / 告白 | 追加新路线或新解锁阶段、终章、后日谈与已发生告白；旧路线逐条保留，关系旧状态进入历史 |

四季第一次各只有一篇完全没问题。以后每次档案增加后，再点对应季节，就会在该季后面增加下一篇。若 Voice 已成功而 Scenario 失败，成功的半篇会先保存；再次点击只补同一批的缺失半篇，不会重做旧篇。

r28/r29 的旧缓存可直接升级。第一次档案增量时，插件先把更新前所有 Mxxx 记成旧内容基线，再让新增 Mxxx 保持待处理；若无法还原旧快照，则保守地把当前档案视为旧基线，避免误复述，下一次档案增量即可正常继续追加。

派生集合采用旧项优先的 240 项安全上限；满额后不会为了腾位置删除旧内容。“今日生活”、设备四时段状态等本来就代表当前状态的字段仍原位更新，它们不是篇目收藏。完全重建正式档案会重编号证据，因此仍会清空不再兼容的派生缓存；普通增量更新不会。

## r29：最大输出 60,000 真正生效

- 设置页“最大输出”现在允许到 **60,000 tokens**，保存/读取不会再被旧 30,000 常量压回。
- JSON 响应的本地解析容量同步提升到 600,000 字符，避免 60k token 长输出先被插件自己截断。
- 报错会同时显示当前插件设置和该功能本段实际请求上限。比如全局设 60,000，但春季 Voice 本段代码只申请 3,000 时，提示会明确显示本段仍是 3,000。
- 60,000 是插件上限，不代表所有模型或代理都接受 60,000；Provider 拒绝时仍按原错误分类处理。

## r28：生成时降低网络占用

- 模型请求进行中不再反复把整个剧场缓存写回 chat metadata；手机 App、Drama Voice/Scenario、ADV 等局部成功会先保存在同一聊天的 runtime cache，等 provider 请求队列空闲后再合并 gzip 并持久化一次。
- 支持 `CompressionStream` 的现代浏览器不再执行“先保存未压缩大缓存 → 再保存压缩缓存”的双写；只有不支持本地 gzip 的旧浏览器才保留未压缩 fallback。
- provider 并发上限仍为 2，r27 的未来/春/夏/秋/冬独立排队、Voice/Scenario 分段与局部成功保存逻辑不变。
- 这项优化只改变派生缓存的持久化时机，不改变正式档案、证据锚点、跨聊天/revision fence；如果页面在生成尚未结束时被强制关闭，尚未完成 idle flush 的最新派生片段可能只存在于本次运行内存中。
- “未来 / 后日谈”是单段 Voice，不再错误显示 `1/2`。

## r27：春夏秋冬可同时排队 / 单季 Voice 与 Scenario 再拆分

- 四季 Voice / Scenario 和未来 Voice 的最低长度适当降低，单请求最大输出也同步缩小，优先保证稳定生成而不是为了硬凑长篇导致整段失败。
- 并发完成时使用 HEART patch 合并，不会出现“春先成功，夏后保存却把春覆盖”的问题。

- **生成禁用词**：默认禁用 `老子`。它只约束相簿 / ADV / 房间 / ENDING / HEART 等新生成派生文本；命中后本次结果失败关闭，不静默替换、不自动重试，历史聊天、正式档案和证据 anchor 原文都不改。
- **房间终于不是一个模子**：卧室、客厅、厨房、书房、音乐/录音工作室、实验室、浴室、餐厅、阳台/庭院、工作间、办公室、营帐/船舱等都有不同固定场景骨架，同类房间再有 3 种稳定布局变体。旧房间缓存若已有明确类型/名称，也会直接使用新布局，无需重生成。

## r18：r17 审计收尾与第三方记忆 reader 显式授权

- **五任务计数补齐**：ADV 批量/逐项恢复、房间“今日生活”和 CG/日常一格绘图都进入统一逻辑并发计数；批量入口在构建 Prompt 前先检查容量，真正发送请求时再做第二次硬检查。

- **Slash Command 兼容收口**：CG/日常一格生图和读取当前连接设置都走统一的公开 `NamedArgumentsCapture` 调用方式，不依赖或伪造 SillyTavern parser 私有参数。
- **只读命名/残留修复**：档案一览函数明确重命名为 snapshot-only 语义，关闭只读后的 UI 刷新不再传入不存在的参数；仍然不会自动切角色/聊天。
- **升级保底缓存不裁剪**：扩展关闭/重载时继续完整保留 runtime theater cache；大缓存只告警，不为了省空间丢相簿/ADV/房间/ENDING/HEART 等已生成数据。

- `CHAT_CHANGED / CHAT_LOADED` 在档案室关闭时不再做档案 UI 维护；长聊天的“可用消息数”也按 chat scope 缓存，仅消息变化时失效。
- 压缩读取增加体积上限，避免恶意或损坏的聊天 metadata 造成异常解压内存占用。

## 这版怎么生成

心跳回忆支持两种互斥的独立 API 来源，均不跟随主聊天连接自动切换：

- **1.1.18 一键配置**：引用 SillyTavern Connection Manager Profile，只保存 Profile ID 与可选模型覆盖，不复制 API Key；运行时按实际 Profile Secret / override 能力校验。
- **手动配置**：保存用户填写的 OpenAI 兼容 Base URL、API Key 与模型 ID。Key 使用 password 输入且不回填界面，只经 SillyTavern 固定同源 custom backend 转发。
- 两种来源不会在失败时互相回退，避免把请求静默发到另一个账号或模型。

- **连接配置**：一键模式决定 Provider / Server URL / Secret ID；手动模式使用显式 Base URL / Key。
- **模型**：两个来源分别保存模型选择，不修改主聊天模型。
- **刷新 / 拉取模型**：只在用户点击时调用 SillyTavern 同源状态接口；一键模式只传 Profile B 的 Secret ID，绝不借用主聊天 Profile A 的 custom headers。

如果 API 不支持列模型，或者服务端状态接口没有返回模型，插件仍会显示该 Connection Profile 本身以及同连接其他已保存 Profile 中出现过的模型作为备用。

## 设置页与档案室

0.8.6 把两种界面彻底分开：

- **插件设置页只负责 API**：1.1.18 一键配置、手动配置、模型刷新/选择、最大输出、温度与每日生活自动请求开关。
- **档案室是独立入口**：可从设置页的“打开档案室”按钮，或 SillyTavern 扩展菜单里的“心跳回忆 · 档案室”进入。
- 档案室负责创建/更新当前聊天档案、查看档案摘要，并提供 **档案室一览**：一个聊天窗口对应一个独立档案；列表只扫描当前角色的聊天窗口。
- 主内容入口为五个：**回忆相簿 → ADV EVENT → 他的房间 → ENDING / 后日谈 → 蝴蝶效应**。
- “他的物品”和“他的手机/私人终端”是“他的房间”内部的深层访问，不再作为档案室头像入口。
- 未生成时不会因为误点头像自动发请求；每张主入口卡片都有自己的“生成这一项”按钮。已经生成的入口可以继续点击头像查看；档案增加后再点“增量追加”，旧内容不会替换。

## 独立生成与并行任务

档案室五个主入口分别请求各自的数据：

- 回忆相簿
- ADV EVENT 事件索引
- 他的房间
- 蝴蝶效应
- ENDING / 后日谈

可以连续点击多个入口，最多 5 项同时后台生成。某一项失败不会让其他入口一起失败，也不会删除之前已经成功保存的内容。

“他的物品 / 私人终端”只从“他的房间”内部进入；如果尚未生成，房间里的对应按钮会主动启动它自己的独立请求。

有两类内容仍然按需单独请求，这是有意设计：

- **长篇 ADV 正文**：用户点开具体 CG 事件时才生成，生成后缓存。
- **他的房间 · 今日生活时间线**：每天属于短期动态状态，不和长期房间蓝图绑死；当天生成后整天只由本地时钟切换节点。

长聊天的“创建/更新档案”仍可能分块请求，因为它需要把历史文本分段整理，不能安全地把超大聊天一次塞进上下文。

0.8.6 不再只截取最近 36 万字符。普通长聊天优先覆盖整个窗口；当前硬上限为 4000 条可用消息 / 约 120 万字符。只有超过这个级别时才会从**整个窗口均匀取样**，而不是只保留近期。分块抽取还会保留真实消息编号，并把不同 messageRange 的相似标题视为不同事件，避免远隔剧情被误去重。档案最多保存 240 条记忆；生成玩法时从整份档案均匀抽取最多 64 条作为模型上下文。

## 真正后台生成

模型生成时不再锁死在 loading 页面。

加载页提供：

- **返回档案室 · 后台继续**
- **关闭 · 后台继续**

关闭后可以继续正常使用 SillyTavern。请求仍然运行，完成后只把结果写回发起任务时绑定的 `chatId + archiveRevision` 缓存，并通过 toast 提示完成。若期间切换聊天或更新档案，迟到结果会被拒绝，不会串档。

重新打开档案室时，如果仍有任务进行，会看到轻量后台任务提示；设置页不会再反复渲染档案卡和玩法按钮。已有缓存仍可浏览，但会阻止再启动第二个模型请求。

## 角色 / 用户 / 世界书上下文

生成时使用受控上下文：

- 当前 `{{char}}` 的角色卡字段（description / personality / scenario / depth prompt / creator notes 等）；
- 当前 `{{user}}` 名称与 SillyTavern Persona description；
- 由“角色设定 + User Persona + 最后一次手动档案”进行 dry-run 后激活的相关世界书；
- 最后一次用户手动创建/更新的聊天档案。

角色卡、Persona 和世界书只负责设定一致性；**过去是否真的发生过**仍然只认手动聊天档案。未归档的新聊天不会因为 Persona / 世界书读取而被偷偷送进生成请求。

## 当前聊天窗口记忆补充

0.8.6 增加“当前窗口记忆桥接”。它只在用户手动点击 **创建聊天档案 / 更新聊天档案** 时工作，不参与 CG、ADV、房间或蝴蝶效应的日常读取。

- 数据边界锁定为当前 `chatId`。切换聊天时正在读取/整理的任务会中止，结果不会写入其他聊天。
- **SillyTavern Memory / Summary**：如果当前聊天存在 `1_memory` 注入的总结，会作为当前窗口的补充资料读取。
- **已注册公开来源**：当前只有 SillyTavern `1_memory` 与柏宝书 Public API v1。柏宝书必须显式声明 `apiVersion === 1`，并返回与当前窗口一致的 chat / revision / coverage；不一致时整份拒绝。
- **r49 已退役旧兼容路径**：不再读取 EverMind 私有 settings / metadata / API Key，也不再扫描全局对象、脚本路径或猜测 reader 方法名。未注册插件只能通过用户明确选择的惰性 JSON / JSONL / TXT / Markdown 导入。
- 心跳回忆不会去扒别的插件私有数据库、DOM、设置、凭据或内部变量，也不会根据来源返回的数据执行任意 URL。公开接口返回值一律只按不可信文本资料处理。
- 外部记忆只在手动建档/更新时同步进心跳回忆自己的 M001... 档案。之后相簿 / ADV / 房间 / 蝴蝶效应仍只读心跳回忆档案，不会每次重新请求外部记忆服务。
- 外部记忆预读取最多接收 256 条 / 约 240,000 字符，并按约 26k 字符分块整理；不会把整库一次塞进模型。每条外部候选记忆都必须返回真实 provider record ID，并通过逐字 `sourceExternalAnchor` 校验后才可进入档案。

档案室提供开关“创建/更新档案时补充读取当前聊天窗口的记忆插件档案”。默认开启；关闭后只扫描聊天正文。

## 升级兼容原则

心跳回忆把“插件版本”和“档案数据 schema”分开管理。升级 0.8.x 不会因为 manifest 版本变化自动删除 `heartbeatMemoriesArchiveV3` 或已生成剧场缓存。未来如果数据结构真的需要升级，必须提供显式迁移；不会把“版本号不一致”当成清空旧档案的理由。

需要区分：用户主动点击“更新聊天档案”会产生新的 archive revision。旧相簿/ADV/房间等如果仍引用旧 revision，会被主动失效，避免把旧证据和新档案混用。这是手动更新档案的行为，不是插件升级行为。

## 聊天档案

每个聊天窗口各自拥有独立档案：

- 第一次由用户手动“创建聊天档案”。
- 后续聊天不会自动进入档案。
- 只有用户主动点“更新档案”，新增聊天才会被重新整理。
- 所有声称“已经发生过”的 ADV EVENT / 回忆 / 与用户有关的房间痕迹，都必须引用真实 `sourceMemoryIds` 并通过 `sourceMemoryAnchor` 证据校验。

### 档案室一览

档案室通过 SillyTavern 同源的 `/api/characters/chats` 以 `simple:true` 只读取**当前角色**的 chat ID / 文件名目录，不再自动扫描所有聊天 metadata。当前聊天自己的档案摘要直接读取当前窗口 metadata；点击一篇非当前历史档案时，使用 `/api/chats/get` 只请求该目标聊天并从 header 提取 Heartbeat metadata，不再读取同角色全部聊天 metadata。SillyTavern 当前没有单篇 metadata-only 接口，因此目标聊天本身仍会完整传输/解析，但不会切换宿主聊天，也不会把正文写进 Heartbeat snapshot、Prompt 或 DOM。列表按角色缓存约 60 秒，也可手动刷新；后台生成期间禁止切换聊天，避免异步回写串档。

## 他的房间：现实时间流动

房间分为长期空间蓝图与短期“今日生活时间线”。每日生活生成 8～14 个节点，之后本地时钟在已有节点间切换，不会每 30 秒请求 API。

r43.0 起，房间外观与房中 CSS 人物会共同采用人物视觉档案：世界书/角色设定的明确描述优先，缺少时按时代、身份、职业、生活方式和气质选择代码内固定枚举。r44.0 进一步固定为侧后/背影视角，删除正脸几何，并用职业兴趣母题和物件种类拉开不同空间的结构；人物始终是与 CSS 场景一致的抽象轮廓，不嵌入档案头像。角色明确养有宠物时，宠物会出现在对应空间；没有明确依据时不会发明。

时间节点可以改变角色所在空间、活动、短台词、光线、窗帘/窗户、整洁程度、桌面用途和少量当天临时物件。与 {{user}} 有关的旧痕迹仍然只能来自手动档案。

如果当天自动生成失败，会落地本地 fallback 并熔断当天自动重试，只有用户手动“更新今日生活”才会再次请求。

房间侧栏新增 **PRIVATE ACCESS**：

- “翻找这里的物品 / 收纳”会进入与当前空间尽量匹配的储物容器。容器不限抽屉，可按世界观使用衣柜、箱笼、行李箱、船舱格、实验室柜、古代匣盒、袖袋、幻想/科幻收纳等，并允许 1～3 层子容器。
- “查看私人通讯终端”在现代可表现为手机；非现代世界会适配为腕式设备、私人终端或传讯器。进入后先显示完整设备主页，点 App 进入列表，再点具体条目进入详情；主题、壁纸、图标和 App 组合随人物与设备变化。地图、导航、路线与出行不再作为终端 App，它们已迁到档案室独立的“他的出行路线”。
- 两者都有“返回他的房间”，不会作为档案室独立入口，也不会因此多发一次基础 API 请求。

## 他的出行路线：近地图对白与远地图明信片

“他的出行路线”是档案室独立入口。模型只提供有证据的地点文字、对白和明信片文案；地图坐标、连线、图标、配色、明信片版式和全部交互均由插件本地固定代码控制。附近地点至少有三句可逐页播放的 {{char}} 对话；远方地点会按海港、雪山、森林、城市等白名单主题绘制本地 SVG/CSS 风景，再叠加明信片文字，不请求或嵌入图片 URL。

## 蝴蝶效应：平行时空观测终端

页面采用垂直双层终端结构，依次包含 Terminal Header、上半区常驻 Divergence Map、下半区 Observation Screen、Reality Intervention 与最底部 dashed System Note。分歧树固定包含锁定主时间线、至少 8 个由角色卡 / User Persona / 相关世界书推演的外延节点，以及末端不同频率发光的 TRUE ENDING / 观测点 Ω。

r43.0 冻结这套界面与动效，只调整内容生成和本地验收；不会把它改成另一套页面，也不会改变既有配色、分歧树、SIGNAL 动画或 Ω 的位置。

点击任一外延节点时，本地先播放 **1 秒 SIGNAL INTERFERENCE / LOADING TEMPORAL DATA**，再切换观测内容。每个平行体独白至少 100 个汉字；现世介入由当前世界的 `{{char}}` 实时自省/告白；系统评价使用冷酷中文算法口吻。外延世界是明确的模拟切片，不要求伪造 `sourceMemoryIds`，也不会写回档案。主时间线仍必须由真实档案锚定。任何前任/前女友，以及 `{{char}}` 与 `{{user}}` 之外的恋爱、婚姻或组建家庭情节仍被禁止。

## Token 与请求频率

“最大输出”是单次输出上限，可在设置页设到 **60,000 tokens**。保留用户自己选择的较低值；插件不会因为升级自动把既有设置抬到 60k。0.8.9.1 起每个入口独立请求，因此不会再为了整套基础包一次性要求超长输出；代价是同时生成多个入口时会分别携带各自需要的上下文。

普通生成最多抽取 64 条均匀覆盖时间线的档案记忆；最终发送前还有约 **32,000 input tokens / 96,000 字符**硬预算，超限直接停止，不发送给模型。60k 是“插件允许请求的输出上限”，不是模型能力保证；模型自身上下文/服务端上限更低时仍可能由 provider 拒绝。

r20 起，创建/更新档案时聊天分块与记忆/摘要分块不再硬限制 4096 输出 tokens，而是使用用户“最大输出”。若模型只产生 reasoning 却没有 final JSON、返回普通文本、JSON 被截断或格式错误，插件会给出不同提示；档案分块只会在你明确确认后额外重试当前这一块一次，不会自动烧第二次请求，也不会先覆盖旧档案。

## 共同回忆与房间深层玩法

- 相簿中每个已解锁 CG 的“共同回忆”不再只有 3 句短评；模型必须生成 **6～8 段**角色回想，覆盖当时注意到的细节、没说出口的念头、对 User 的观察、情绪转折、事后理解和现在回看时的感受。

- `getSnapshot()` 与 `getInjectedHistory()` 会合并读取；外部记忆扩大到最多 256 条 / 24 万字符并分块整理，避免只吃到当前注入的少量记忆。

## 当前窗口记忆 / 摘要兼容（r11 历史行为）

> 历史说明：以下三路是 r11 当时的兼容策略。r49 已删除第 1 项的未知全局方法猜测以及第 2、3 项的任意 prompt / metadata 启发式扫描；当前生产版本只保留精确 `1_memory`、柏宝书 Public API v1 和用户显式文件导入。

当时建档会按顺序尝试：

1. 能明确表示“当前聊天”的公开 API（`getInjectedHistory`、`getCurrentChatMemories`、`getCurrentChatMemory`、`getCurrentChatSummary`、`getCurrentSummary`）；
2. 当前 SillyTavern prompt 中明确标为 memory / summary / 摘要 / 总结的注入文本；
3. 当前聊天 `chatMetadata` 中明确标为摘要/记忆的数据。

所有补充资料都要经过 externalId + 原文 anchor 校验。世界书、角色卡、作者注记属于设定上下文，不作为“某件事已经发生”的证据；原始当前聊天正文仍是最可靠的事实来源。

### r13: incremental archives and read-only archive browsing

- “更新当前窗口档案” is incremental by default: it only processes chat messages added after the previous archive plus changed current-chat memory/summary sources. Existing Mxxx IDs and generated Album/ADV EVENT/Room/Ending/Items/Phone content are retained.
- If an already archived message was edited/deleted/reordered, the incremental update stops. Use the separate “完全重建档案” only when you intentionally want a full rescan and are willing to invalidate derived content.
- ADV bulk generation no longer auto-retries every failure individually. After a partial failure, choose either one more bulk request or an explicitly confirmed per-item repair pass.
- Opening another character/chat archive from the archive library is read-only and does not switch the SillyTavern chat. Generated content can be viewed from saved metadata; mutation/generation actions remain disabled until you intentionally return to that chat.
