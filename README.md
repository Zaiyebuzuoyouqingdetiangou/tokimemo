# 心跳回忆 0.8.10 r30

## r30：所有内容都在原有基础上增量增加

先像以前一样点击“增量更新当前窗口档案”，让正式档案追加新的 Mxxx；然后在想扩充的内容入口点击“增量追加”。每一项都有自己的本地消费游标，只读取尚未用于该项的新 Mxxx。没有新记忆时会直接提示，不会调用模型，也不会把旧内容再讲一次。

| 内容 | r30 的追加行为 |
|---|---|
| 回忆相簿 | 追加新 CG 节点和共同回忆；旧描述、评论与已绘制图片保持不变 |
| CG / ADV | 追加新事件索引；旧 CG 图片和已完成 ADV 全文保持不变 |
| 他的房间 / 物品 | 向既有空间、容器追加新证据物件，必要时增加新空间/容器；旧文字不改 |
| 私人终端 | 在既有 App 后追加新条目；旧聊天、照片文字档案、联系人等不重做 |
| 蝴蝶效应 | 追加新平行分歧；上一轮 Ω 保存为历史观测，再生成新的 Ω |
| ENDING / 告白 | 追加新路线或新解锁阶段、终章、后日谈与已发生告白；旧路线逐条保留，关系旧状态进入历史 |
| 成就库 | 追加新里程碑；旧的未解锁目标可在新证据下升级为解锁 |
| HEART 对话 / 一格 | 分别追加新时期对话、特别日和日常一格 |
| 未来 / 春 / 夏 / 秋 / 冬 | 每一季有独立游标；同一季可以保存多篇 Voice / Scenario，补春篇不会消耗夏秋冬的新档案 |

四季第一次各只有一篇完全没问题。以后每次档案增加后，再点对应季节，就会在该季后面增加下一篇。若 Voice 已成功而 Scenario 失败，成功的半篇会先保存；再次点击只补同一批的缺失半篇，不会重做旧篇。

r28/r29 的旧缓存可直接升级。第一次档案增量时，插件先把更新前所有 Mxxx 记成旧内容基线，再让新增 Mxxx 保持待处理；若无法还原旧快照，则保守地把当前档案视为旧基线，避免误复述，下一次档案增量即可正常继续追加。

派生集合采用旧项优先的 240 项安全上限；满额后不会为了腾位置删除旧内容。“今日生活”、设备四时段状态等本来就代表当前状态的字段仍原位更新，它们不是篇目收藏。完全重建正式档案会重编号证据，因此仍会清空不再兼容的派生缓存；普通增量更新不会。

## r29：最大输出 60,000 真正生效

- 设置页“最大输出”现在允许到 **60,000 tokens**，保存/读取不会再被旧 30,000 常量压回。
- JSON 响应的本地解析容量同步提升到 600,000 字符，避免 60k token 长输出先被插件自己截断。
- 报错会同时显示当前插件设置和该功能本段实际请求上限。比如全局设 60,000，但春季 Voice 本段代码只申请 3,000 时，提示会明确显示本段仍是 3,000。
- 60,000 是插件上限，不代表所有模型或代理都接受 60,000；Provider 拒绝时仍按原错误分类处理。

## r28：生成时降低网络占用

- 模型请求进行中不再反复把整个剧场缓存写回 chat metadata；手机 App、Drama Voice/Scenario、ADV 等局部成功会先保存在同一聊天的 runtime cache，等 provider 请求队列空闲后再合并 gzip 并持久化一次。
- 支持 `CompressionStream` 的现代浏览器不再执行“先保存未压缩大缓存 → 再保存压缩缓存”的双写；只有不支持本地 gzip 的旧浏览器才保留未压缩 fallback。
- provider 并发上限仍为 2，r27 的未来/春/夏/秋/冬独立排队、Voice/Scenario 分段与局部成功保存逻辑不变。
- 这项优化只改变派生缓存的持久化时机，不改变正式档案、证据锚点、跨聊天/revision fence；如果页面在生成尚未结束时被强制关闭，尚未完成 idle flush 的最新派生片段可能只存在于本次运行内存中。
- “未来 / 后日谈”是单段 Voice，不再错误显示 `1/2`。

## r27：春夏秋冬可同时排队 / 单季 Voice 与 Scenario 再拆分

- 未来、春、夏、秋、冬不再共享一个生成锁，可以连续点击多个季节。插件最多允许 5 个逻辑任务排队，但 Connection Manager 仍最多同时发送 2 个请求。
- 春夏秋冬每一季拆成两个独立小段：Voice Drama 与 Scenario Drama。成功一段就立刻保存；若只成功一段，页面显示 `1/2`，再次点击只补缺失的一段。
- 四季 Voice / Scenario 和未来 Voice 的最低长度适当降低，单请求最大输出也同步缩小，优先保证稳定生成而不是为了硬凑长篇导致整段失败。
- 并发完成时使用 HEART patch 合并，不会出现“春先成功，夏后保存却把春覆盖”的问题。

## r26：设置说明清空 / 终端续写 / Drama 逐季生成

- **设置页继续瘦身**：保留连接、模型、刷新、最大输出、温度、禁用词与两个勾选控件；删除勾选项下方从“专用连接：…”到“模型刷新只调用…”的整块灰色说明文字。
- **角色 / user 标签改真实姓名**：日常一格以及 Drama 剧本行不再显示“角色”“剧本中的你”，改用当前 char 名称和当前 user 名称；只读历史档案优先使用该档案保存的角色 / user 名称。
- **私人终端支持失败续写**：目录生成后，每完成一个 App 就保存精简、已校验的续写草稿。中途失败时房间按钮显示“继续生成… · 已完成/总数”，续写跳过已经完成的 App，不再从头请求。草稿只绑定同一 chatId + archiveRevision；档案更新或终端完整保存后自动清除。
- **春夏秋冬 Drama 改为逐季按钮**：未来/后日谈、春、夏、秋、冬各自单独生成并立即保存。某一季失败不会再让前面已经成功的季节全部作废。
- **r24 请求协调器与 r25 证据边界不变**：Provider 限流、超时、重试白名单、原子写入、memory ID/anchor 校验与只读保护继续保留。

## r25：重要节点增量收藏 / 三分角色互动 / 成就库


- **回忆相簿与 CG/ADV 不再凑固定数量**：每次只抓当前档案里约 3～6 个最重要、最适合做 CG 的节点，与旧收藏增量合并。共同回忆每张 4～6 段，界面不再显示“现在的他 → 现在的你”。
- **ADV 一批最多 6 篇**：收藏可以一直累积，但每次批量正文只生成最多 6 篇，避免以后节点越来越多又把一个请求撑爆。
- **告白回看才使用头像逐句对话**：只有已经发生、能通过档案证据校验的告白进入播放器；ENDING 未来路线不再放头像告白。
- **角色互动分三块单独生成**：各种时期的对话 / 春夏秋冬·Drama / 日常一格。首次只做时期对话；四季再拆成后日谈与春夏秋冬小请求；日常一格独立生成。
- **私人终端更轻**：手机仍保留 10 类 App，但总条目约 32～33 条，深聊改为 2 个 × 12 条左右；其它设备进一步按能力压缩。
- **档案室新增成就库**：已解锁 / 未解锁分区。已解锁必须有真实 memory ID + anchor；未解锁只显示条件和提示。
- **界面说明大幅精简**：保留必要状态、错误、只读和确认，其余重复说明删除。r24 的请求协调器、超时、限流和原子提交继续保留。

## r24：生成协调器修复 / 头像逐句告白

- **不会再被自己的分段挤满任务位**：一个相簿、私人终端、角色互动或 ENDING 只算一个逻辑任务；内部小请求由统一队列控制，同时最多 2 个真正发往模型。
- **不会无限转圈**：单次模型请求默认最多等待 5 分钟，超时后释放任务位并保留旧内容。认证、429、上下文超限、配置错误和上游故障会显示不同提示。
- **分段改为稳定顺序**：同一模式内部不再三路同时轰 API；结构目录使用较低温度，正文继续使用用户设置的创作温度。内容数量和本地校验门槛没有降低。
- **ENDING 是角色亲口告白**：可用路线用角色卡本地头像、姓名框和单句对话框播放 6～10 句第一人称告白，并提供上一句、下一句、重播。旧 ENDING 缓存也会本地拆句显示。

## r23：大生成项稳定化 / ENDING 并行提速

- **私人终端**：先生成设备/App/条目目录，再按 App 并行补详情；不再一次要求 65+ 条目和全部深聊。phone 保留完整内容量，手表/传讯器不再被错误要求和手机一样的 3 个 24 消息深聊。
- **回忆相簿**：15+ 张 CG 的目录/证据先生成；共同回忆按每 4 张一组并行生成，仍然是“现在的角色陪现在的用户看过去 CG”。
- **角色互动 / Voice Drama**：基础问候包、后日谈 Voice、四季 Voice、四季 Scenario 分段；后 3 段并行生成并分别校验。
- **ENDING**：目录与告白回看同时跑；已解锁路线正文最多 3 路并行。原来的证据锚点、失败关闭、旧缓存保护不变。
- 这些分段单次请求最高只需约 5.5k～12k 输出，默认 16,384 tokens 不再需要承担“一个 JSON 塞完整个模式”的压力；如果用户主动设置得更低，仍尊重用户设置。

## r22：ENDING 分段 / 共同回忆当下陪看 / 生图手动兜底

- **ENDING 不再一次生成全部**：先生成关系与路线目录，再单独扫描已发生告白，最后对已解锁路线逐条生成长篇终章与后日谈。这样单次请求更短；某条路线短请求失败会只重试该条，仍失败则不会覆盖旧 ENDING。
- **共同回忆不是 ADV**：点击相簿里的“共同回忆”后，定位是“现在的他和现在的你一起看过去的 CG”。新生成的相簿评论会直接对现在的你说话、评价当时与现在的变化，不再写成过去时长篇内心回放。
- **生图检测更宽 + 可手动确认**：除了 `/imagine` 也检查 `/sd` / `/img`。如果你的 Image Generation 明明已开启但自动检测仍失败，可在心跳回忆设置中勾选“手动确认 Image Generation 已启用”；绘制时会用受控 `/sd quiet=true` 兜底。

## r21：角色版本分类 / 禁用词 / 房间差异化

- **char / char 2.0 不再因为共用头像自动挤进同一组**：新写入或手动重扫的档案索引会保存角色卡内容指纹并优先按指纹分类；没有指纹的旧索引仍可在“管理角色分类”里手动拆分。
- **管理角色分类**：支持“一键自动分类未锁定档案”、把某个聊天档案移动到现有角色组，以及从 SillyTavern 当前角色列表里手动选择一个 char 新建角色组。这里只改心跳回忆的展示索引，不移动/重命名/删除酒馆聊天文件。
- **旧版本歧义不乱猜**：旧档案若没有角色卡指纹，而 SillyTavern 里又存在多个同头像/同名候选，会显示成独立的“待手动分类”。你可以逐条移动到正确组；手动归类以后自动分类不会再覆盖。
- **删除档案**：当前真实聊天提供“删除当前档案”，必须连续确认两次，只删除 Heartbeat 的 `MEMORY_KEY` 与相簿/CG/ADV/房间/ENDING/HEART 等派生缓存，聊天正文不动。其它历史档案提供“从档案室移除”，只删轻量索引，不会偷偷切聊天或删除酒馆聊天文件。
- **生成禁用词**：默认禁用 `老子`。它只约束相簿 / ADV / 房间 / ENDING / HEART 等新生成派生文本；命中后本次结果失败关闭，不静默替换、不自动重试，历史聊天、正式档案和证据 anchor 原文都不改。
- **房间终于不是一个模子**：卧室、客厅、厨房、书房、音乐/录音工作室、实验室、浴室、餐厅、阳台/庭院、工作间、办公室、营帐/船舱等都有不同固定场景骨架，同类房间再有 3 种稳定布局变体。旧房间缓存若已有明确类型/名称，也会直接使用新布局，无需重生成。

## r18：r17 审计收尾与第三方记忆 reader 显式授权

- **五任务计数补齐**：ADV 批量/逐项恢复、房间“今日生活”和 CG/日常一格绘图都进入统一逻辑并发计数；批量入口在构建 Prompt 前先检查容量，真正发送请求时再做第二次硬检查。
- **第三方记忆 reader 默认关闭**：普通 SillyTavern Memory 注入摘要和当前聊天 metadata 摘要仍可直接作为补充来源；只有你主动勾选“允许调用第三方记忆插件公开 current-chat 读取函数”后，心跳回忆才会执行其它扩展公开的 current-chat reader。
- **Slash Command 兼容收口**：CG/日常一格生图和读取当前连接设置都走统一的公开 `NamedArgumentsCapture` 调用方式，不依赖或伪造 SillyTavern parser 私有参数。
- **只读命名/残留修复**：档案一览函数明确重命名为 snapshot-only 语义，关闭只读后的 UI 刷新不再传入不存在的参数；仍然不会自动切角色/聊天。
- **升级保底缓存不裁剪**：扩展关闭/重载时继续完整保留 runtime theater cache；大缓存只告警，不为了省空间丢相簿/ADV/房间/ENDING/HEART 等已生成数据。


## r17：档案状态修复、告白单独刷新与五入口并行

- **告白回看单独更新**：在 ENDING → 告白回看中点击“只重新读取告白”，只扫描后来新增/更新到档案里的真实告白节点。原有结局路线、逆转告白和后日谈不变。
- **五个主入口最多并行 5 项**：回忆相簿、CG/ADV、房间、ENDING、蝴蝶效应可以同时各跑一个主任务；仍禁止同一个入口重复启动。
- **只读开关不再切聊天**：从全角色档案馆打开旧档案仍默认只读。关闭只读只让编辑按钮出现，不会自动切角色、聊天或刷新酒馆。真正写入时必须是用户已经手动打开的同角色/同 chatId live 聊天，否则只提示、不写入。
- **CG 生图动态重检**：相簿和 CG/ADV 的状态条提供“重新检测”。先开档案、后启动 Image Generation 也可以立刻重新检测，不需要重开档案。
- **快照不能覆盖 live 缓存**：即使关闭只读，历史 snapshot 也只用于浏览；写入前必须重新取得 live session，缺失时 fail closed。

### r16：角色互动、Voice Drama、四季小剧场与日常一格

- 档案室的角色头像现在是互动入口。已有 HEART 缓存时，点击头像会依据本地现实时间、周末、角色生日/用户生日（仅设定明确时）/特别日以及“距离上次点头像多久”弹出符合人设的台词；3 天左右偏担心、7 天以上可闹别扭、14 天以上在关系合适时可轻度吃醋。点击头像本身不会发模型请求。
- 新增 `HEART / 角色互动与 Voice Drama`：包含后日谈长篇生活剧场、春夏秋冬 Voice Drama、春夏秋冬 Scenario Drama 和“日常一格”。这些内容是明确标注的附加演出/未来模拟，不写入正式 MEMORY_KEY 档案。
- “日常一格”先保存 1/2/4 格的文字分镜和台词；可选使用 SillyTavern 已配置的 Image Generation 绘制 Q 版漫画。图片 prompt 明确要求无文字/无对白框/无水印，真正台词由界面单独显示。
- ENDING 新增 `逆转告白` 路线。只有当前档案已有可验证的强烈依恋与“差点错过/竞争/吃醋/关系位置流失”压力时才会解锁；普通暧昧不会硬开。

## 0.8.10 r14：CG 生图入口可见性

### r15：只读保护开关与告白回看

- 从全角色档案馆打开的历史档案默认只读。关闭“只读查看”只显示编辑按钮，绝不会自动切角色、聊天或刷新宿主界面；真正写入前必须由用户自己在 SillyTavern 打开对应聊天，并再次通过角色 + chatId + 档案身份校验。每次增量追加仍有独立确认。
- ENDING 增加“告白回看”页，只从手动档案中已经发生、能通过 memory ID + anchor 验证的告白/关系确认生成回看。没有证据就不生成。
- “告白回看”是过去事件的档案式重构；ENDING 路线中的 confession 仍是未来终章推演，两者不会混淆。


- 回忆相簿中每张已解锁 CG 的缩略图右下角直接提供 **“🎨 绘制 / ↻ 重绘”**，不必先进入详情。
- CG/ADV 详情增加 **“CG 实图 · Image Generation 已连接 / 未检测到”** 状态条，绘制按钮固定放在操作区最前。
- 如果从全角色档案馆点开的条目就是 SillyTavern 当前正在打开的同一角色、同一聊天档案，会自动回到可写的 live 档案；真正的其他历史档案仍只读，且不会为了绘图自动切聊天。

## 0.8.10 r12：CG 实图绘制

- 相簿已解锁 CG 和 CG/ADV 事件都新增 **“🎨 绘制CG”**。如果 SillyTavern 已启用并配置官方 Image Generation 扩展，点击后会使用其 `imagine` 命令生成图片，并覆盖原来的抽象 CG；没有插件、生成失败或图片失效时继续显示抽象 CG。

- 新生成的 CG 数据会额外带一个纯视觉 `imagePrompt`；旧缓存无需重做，会从原 `desc/cgDesc + visualSeed` 生成 fallback。心跳回忆不会把完整聊天、档案、世界书或私人终端内容交给生图扩展。
- 图片由 SillyTavern Image Generation 自己保存；心跳回忆只保存同源本地图片路径，不保存 base64，也不直接读取或管理任何生图服务 API Key。

## 0.8.9.1 独立入口并行生成

- 移除“生成整套档案室内容”一键基础包入口。回忆相簿、CG/ADV 事件索引、他的房间、蝴蝶效应、ENDING / 后日谈都采用**各自首次生成 / 增量追加**，每一项只承担自己的 Prompt、游标与 JSON 校验，避免整包过长导致一次失败全部失败。
- 五个主入口共用最多 **5 项并行生成** 的安全上限。每个任务使用独立 AbortController、原 chatId、characterKey 与 archiveRevision；同一聊天切走后继续后台运行，完成后只写回原窗口。
- 同一入口禁止重复启动；不同入口可以同时请求。CG/ADV 的具体长篇正文仍按单个事件生成，同一个聊天同一时刻只允许一篇具体 ADV，避免并发覆盖事件缓存。
- “他的物品 / 私人终端”继续没有档案室独立入口。进入“他的房间”后，如果对应深层内容尚未生成，按钮会变成“生成并翻找 / 生成并查看”，可与其他主入口同时后台生成。
- 并行任务完成时采用按 mode 合并的延迟写回，避免用户切到别的聊天后两个不同入口先后完成、后一个结果把前一个 deferred session 覆盖掉。
- 创建/更新聊天档案、重新读取记忆插件仍属于档案级操作：有内容生成任务时会暂时禁止，以防 archiveRevision 在并行任务中途变化。

## 0.8.10 r9：ENDING 与纯文字相册

- 私人终端 Gallery 不再读取/请求世界书里的外部图片地址，只保留照片分类、标题、预览、正文和 `imageCaption` 的文字照片档案。
- 档案室新增独立 `ENDING / 后日谈`。当前关系状态和每条路线都有真实档案锚点；结局场景与后日谈明确属于未来推演，不写回正式档案。
- 至少包含当前路线、恋爱、羁绊、开放四类结局。恋爱关系证据不足时显示未解锁条件，不会硬把暧昧写成已经交往。已解锁路线包含 3+ 段后日谈生活切片。

## 0.8.8 档案保留与聊天进入性能修复

- **插件版本升级不再等同于档案 schema 升级。** 0.8.8 继续使用稳定的 `heartbeatMemoriesArchiveV3` / schema v3；0.8.x 正常升级不会删除、重建或判废旧档案。只有用户主动“更新聊天档案”时，才会产生新的 archive revision，并按证据一致性失效旧的派生剧场内容。
- **已生成剧场内容继续保留。** 相簿、ADV、房间、物品、私人终端、蝴蝶效应仍跟随对应聊天保存；版本更新、初始化、切换聊天都不会主动清空。
- 修复电脑端进入长聊天时 CPU 突升的主要放大器：0.8.7 以前把完整剧场缓存作为巨大嵌套对象直接放进 `chat_metadata`。ADV 越多，聊天文件第一行越大；SillyTavern 打开聊天时必须整文件读取并 JSON 解析这些内容。
- 0.8.8 将**剧场缓存**改为 `gzip + Base64` 压缩后仍保存在同一个聊天 metadata 中，因此不会变成本机专属缓存，也不会因为升级插件而丢失；普通聊天打开时只需要解析压缩字符串，真正打开“心跳回忆”档案室时才解压。
- 旧版未压缩缓存采用**懒迁移**：第一次进入旧聊天仍能读取旧数据，浏览器空闲时会把它压缩后原位保存。第一次迁移可能仍有一次短暂 CPU 占用，之后同一聊天的进入成本会明显下降。
- 解压后的运行时剧场缓存只保留最近 3 个聊天窗口，避免长时间切换多个角色后把全部 ADV / 房间内容常驻内存。
- `CHAT_CHANGED / CHAT_LOADED` 在档案室关闭时不再做档案 UI 维护；长聊天的“可用消息数”也按 chat scope 缓存，仅消息变化时失效。
- 压缩读取增加体积上限，避免恶意或损坏的聊天 metadata 造成异常解压内存占用。

## 0.8.6 重点

- 当前聊天档案改为**全窗口覆盖优先**：长聊天不再只截取最近 36 万字符；超出硬上限时按整个窗口均匀取样，并保留原消息编号。
- 档案整理真正后台化：聊天扫描分批让出主线程，档案分块不再重复执行高成本 token 计数，进度只更新轻量状态文字。
- “共同回忆”由 3 句浅评论升级为 **6～8 段角色回想**。
- “他的物品 / 他的手机”不再占用档案室独立入口：两者都收回 **“他的房间”内部**，从私人空间里继续翻找收纳或查看符合时代设定的私人通讯终端。
- 档案室新增 **“档案室一览”**：当前角色的每个聊天窗口各自对应一份独立心跳回忆档案，可查看有无建档、档案名、记忆数量与更新时间，并安全切换到对应聊天。
- 当前窗口记忆桥接支持通用公开接口适配，但 r18 起**默认不执行第三方 reader**。用户显式开启后，可识别 `getInjectedHistory()` / `getCurrentChatMemories()` / `getCurrentChatMemory()` / `getCurrentChatSummary()` / `getCurrentSummary()` 与可选 `getSnapshot()`；调用前后都校验仍处于发起时的聊天窗口。
- 蝴蝶效应恢复原始“时间分歧树”设计：主时间线由真实档案锚定；8+ 平行外延节点改由角色卡 + User Persona + 相关世界书推演，最后附 TRUE ENDING 彩蛋；平行世界明确是模拟，不会写回档案。
- 0.8.9.1 起取消整套基础包请求：相簿、CG/ADV、房间、蝴蝶效应分别生成，可最多 5 项并行；长篇 ADV 正文继续按具体事件点开后单独生成。

独立 SillyTavern 第三方扩展。与兔子镜无依赖、无共享运行时。

## 这版怎么生成

心跳回忆固定使用一个 **SillyTavern Connection Manager Profile**，不跟随主聊天连接自动切换。

设置页把“连接”和“模型”分成两层：

- **连接配置**：决定 Provider / Server URL / Secret ID / Preset 等。
- **模型**：可以在同一个连接下面单独选择心跳回忆使用的模型，不修改主聊天模型。
- **刷新模型**：调用 SillyTavern 自己的同源状态接口读取该连接可见的模型。插件浏览器端只传 Secret ID 引用，不读取或显示 API Key 明文。

如果 API 不支持列模型，或者服务端状态接口没有返回模型，插件仍会显示该 Connection Profile 本身以及同连接其他已保存 Profile 中出现过的模型作为备用。

## 设置页与档案室

0.8.6 把两种界面彻底分开：

- **插件设置页只负责 API**：一键导入 Connection Manager、连接配置、模型刷新/选择、最大输出、温度与每日生活自动请求开关。
- **档案室是独立入口**：可从设置页的“打开档案室”按钮，或 SillyTavern 扩展菜单里的“心跳回忆 · 档案室”进入。
- 档案室负责创建/更新当前聊天档案、查看档案摘要，并提供 **档案室一览**：一个聊天窗口对应一个独立档案；列表只扫描当前角色的聊天窗口。
- 主内容入口为五个：**回忆相簿 → CG/ADV → 他的房间 → ENDING / 后日谈 → 蝴蝶效应**。
- “他的物品”和“他的手机/私人终端”是“他的房间”内部的深层访问，不再作为档案室头像入口。
- 未生成时不会因为误点头像自动发请求；每张主入口卡片都有自己的“生成这一项”按钮。已经生成的入口可以继续点击头像查看；档案增加后再点“增量追加”，旧内容不会替换。

## 独立生成与并行任务

档案室五个主入口分别请求各自的数据：

- 回忆相簿
- CG / ADV 事件索引
- 他的房间
- 蝴蝶效应
- ENDING / 后日谈

可以连续点击多个入口，最多 5 项同时后台生成。某一项失败不会让其他入口一起失败，也不会删除之前已经成功保存的内容。

“他的物品 / 私人终端”只从“他的房间”内部进入；如果尚未生成，房间里的对应按钮会主动启动它自己的独立请求。

有两类内容仍然按需单独请求，这是有意设计：

- **长篇 ADV 正文**：用户点开具体 CG 事件时才生成，生成后缓存。
- **他的房间 · 今日生活时间线**：每天属于短期动态状态，不和长期房间蓝图绑死；当天生成后整天只由本地时钟切换节点。

长聊天的“创建/更新档案”仍可能分块请求，因为它需要把历史文本分段整理，不能安全地把超大聊天一次塞进上下文。

0.8.6 不再只截取最近 36 万字符。普通长聊天优先覆盖整个窗口；当前硬上限为 4000 条可用消息 / 约 120 万字符。只有超过这个级别时才会从**整个窗口均匀取样**，而不是只保留近期。分块抽取还会保留真实消息编号，并把不同 messageRange 的相似标题视为不同事件，避免远隔剧情被误去重。档案最多保存 240 条记忆；生成玩法时从整份档案均匀抽取最多 64 条作为模型上下文。

## 真正后台生成

模型生成时不再锁死在 loading 页面。

加载页提供：

- **返回档案室 · 后台继续**
- **关闭 · 后台继续**

关闭后可以继续正常使用 SillyTavern。请求仍然运行，完成后只把结果写回发起任务时绑定的 `chatId + archiveRevision` 缓存，并通过 toast 提示完成。若期间切换聊天或更新档案，迟到结果会被拒绝，不会串档。

重新打开档案室时，如果仍有任务进行，会看到轻量后台任务提示；设置页不会再反复渲染档案卡和玩法按钮。已有缓存仍可浏览，但会阻止再启动第二个模型请求。

## 角色 / 用户 / 世界书上下文

生成时使用受控上下文：

- 当前 `{{char}}` 的角色卡字段（description / personality / scenario / depth prompt / creator notes 等）；
- 当前 `{{user}}` 名称与 SillyTavern Persona description；
- 由“角色设定 + User Persona + 最后一次手动档案”进行 dry-run 后激活的相关世界书；
- 最后一次用户手动创建/更新的聊天档案。

角色卡、Persona 和世界书只负责设定一致性；**过去是否真的发生过**仍然只认手动聊天档案。未归档的新聊天不会因为 Persona / 世界书读取而被偷偷送进生成请求。

## 当前聊天窗口记忆补充

0.8.6 增加“当前窗口记忆桥接”。它只在用户手动点击 **创建聊天档案 / 更新聊天档案** 时工作，不参与 CG、ADV、房间或蝴蝶效应的日常读取。

- 数据边界锁定为当前 `chatId`。切换聊天时正在读取/整理的任务会中止，结果不会写入其他聊天。
- **SillyTavern Memory / Summary**：如果当前聊天存在 `1_memory` 注入的总结，会作为当前窗口的补充资料读取。
- **EverMind**：如果检测到启用的 EverMind 且当前聊天 metadata 中存在该窗口自己的 `group_id`，只读取这个 `group_id`；不会读取 `char_group_id` 或角色级跨聊天记忆。
- **公开记忆插件接口（显式授权）**：默认关闭第三方 reader 执行。开启后只检测明确的 current-chat reader：`getInjectedHistory()` / `getCurrentChatMemories()` / `getCurrentChatMemory()` / `getCurrentChatSummary()` / `getCurrentSummary()`，并可选读取 `getSnapshot()` 的 `chat / coverage / revision` 信息。若接口明确返回的聊天 ID 与当前窗口不一致，整份来源直接拒绝；异步读取前后也会再次核对当前 `chatId`。
- 心跳回忆不会去扒别的插件私有数据库、DOM 或内部变量，也不会根据插件返回的数据去执行任意 URL；公开接口返回值一律只按不可信文本资料处理。
- EverMind 的 API Key 只在一次请求的内存中作为该记忆插件已有凭据使用；不会复制到心跳回忆设置、档案、日志、DOM 或模型 Prompt。
- 外部记忆只在手动建档/更新时同步进心跳回忆自己的 M001... 档案。之后相簿 / ADV / 房间 / 蝴蝶效应仍只读心跳回忆档案，不会每次重新请求外部记忆服务。
- 外部记忆预读取最多接收 256 条 / 约 240,000 字符，并按约 26k 字符分块整理；不会把整库一次塞进模型。每条外部候选记忆都必须返回真实 provider record ID，并通过逐字 `sourceExternalAnchor` 校验后才可进入档案。

档案室提供开关“创建/更新档案时补充读取当前聊天窗口的记忆插件档案”。默认开启；关闭后只扫描聊天正文。

## 升级兼容原则

心跳回忆把“插件版本”和“档案数据 schema”分开管理。升级 0.8.x 不会因为 manifest 版本变化自动删除 `heartbeatMemoriesArchiveV3` 或已生成剧场缓存。未来如果数据结构真的需要升级，必须提供显式迁移；不会把“版本号不一致”当成清空旧档案的理由。

需要区分：用户主动点击“更新聊天档案”会产生新的 archive revision。旧相簿/ADV/房间等如果仍引用旧 revision，会被主动失效，避免把旧证据和新档案混用。这是手动更新档案的行为，不是插件升级行为。

## 聊天档案

每个聊天窗口各自拥有独立档案：

- 第一次由用户手动“创建聊天档案”。
- 后续聊天不会自动进入档案。
- 只有用户主动点“更新档案”，新增聊天才会被重新整理。
- 所有声称“已经发生过”的 CG / ADV / 回忆 / 与用户有关的房间痕迹，都必须引用真实 `sourceMemoryIds` 并通过 `sourceMemoryAnchor` 证据校验。

### 档案室一览

档案室通过 SillyTavern 同源的 `/api/characters/chats` 以 `simple:true` 只读取**当前角色**的 chat ID / 文件名目录，不再自动扫描所有聊天 metadata。当前聊天自己的档案摘要直接读取当前窗口 metadata；其他聊天在实际进入后再记住轻量摘要。列表按角色缓存约 60 秒，也可手动刷新。点击非当前条目时，只允许打开本轮 SillyTavern 返回的 chat ID；后台生成期间禁止切换聊天，避免异步回写串档。

## 他的房间：现实时间流动

房间分为长期空间蓝图与短期“今日生活时间线”。每日生活生成 8～14 个节点，之后本地时钟在已有节点间切换，不会每 30 秒请求 API。

时间节点可以改变角色所在空间、活动、短台词、光线、窗帘/窗户、整洁程度、桌面用途和少量当天临时物件。与 {{user}} 有关的旧痕迹仍然只能来自手动档案。

如果当天自动生成失败，会落地本地 fallback 并熔断当天自动重试，只有用户手动“更新今日生活”才会再次请求。

房间侧栏新增 **PRIVATE ACCESS**：

- “翻找这里的物品 / 收纳”会进入与当前空间尽量匹配的储物容器。容器不限抽屉，可按世界观使用衣柜、箱笼、行李箱、船舱格、实验室柜、古代匣盒、袖袋、幻想/科幻收纳等，并允许 1～3 层子容器。
- “查看私人通讯终端”在现代可表现为手机；非现代世界会适配为私人终端/传讯器。
- 两者都有“返回他的房间”，不会作为档案室独立入口，也不会因此多发一次基础 API 请求。

## 蝴蝶效应：平行时空观测终端

页面采用垂直双层终端结构，依次包含 Terminal Header、上半区常驻 Divergence Map、下半区 Observation Screen、Reality Intervention 与最底部 dashed System Note。分歧树固定包含锁定主时间线、至少 8 个由角色卡 / User Persona / 相关世界书推演的外延节点，以及末端不同频率发光的 TRUE ENDING / 观测点 Ω。

点击任一外延节点时，本地先播放 **1 秒 SIGNAL INTERFERENCE / LOADING TEMPORAL DATA**，再切换观测内容。每个平行体独白至少 100 个汉字；现世介入由当前世界的 `{{char}}` 实时自省/告白；系统评价使用冷酷中文算法口吻。外延世界是明确的模拟切片，不要求伪造 `sourceMemoryIds`，也不会写回档案。主时间线仍必须由真实档案锚定。任何前任/前女友，以及 `{{char}}` 与 `{{user}}` 之外的恋爱、婚姻或组建家庭情节仍被禁止。

## Token 与请求频率

“最大输出”是单次输出上限，可在设置页设到 **60,000 tokens**。保留用户自己选择的较低值；插件不会因为升级自动把既有设置抬到 60k。0.8.9.1 起每个入口独立请求，因此不会再为了整套基础包一次性要求超长输出；代价是同时生成多个入口时会分别携带各自需要的上下文。

普通生成最多抽取 64 条均匀覆盖时间线的档案记忆；最终发送前还有约 **32,000 input tokens / 96,000 字符**硬预算，超限直接停止，不发送给模型。60k 是“插件允许请求的输出上限”，不是模型能力保证；模型自身上下文/服务端上限更低时仍可能由 provider 拒绝。

r20 起，创建/更新档案时聊天分块与记忆/摘要分块不再硬限制 4096 输出 tokens，而是使用用户“最大输出”。若模型只产生 reasoning 却没有 final JSON、返回普通文本、JSON 被截断或格式错误，插件会给出不同提示；档案分块只会在你明确确认后额外重试当前这一块一次，不会自动烧第二次请求，也不会先覆盖旧档案。

## 共同回忆与房间深层玩法

- 相簿中每个已解锁 CG 的“共同回忆”不再只有 3 句短评；模型必须生成 **6～8 段**角色回想，覆盖当时注意到的细节、没说出口的念头、对 User 的观察、情绪转折、事后理解和现在回看时的感受。
- 房间内的“翻找物品”不是固定现代抽屉 UI。模型可以按时代/职业/居住环境生成衣柜、床头柜、箱笼、行李箱、旅行袋、工具箱、药箱、首饰盒、储物柜、古代匣盒、袖袋、船舱储物格、实验室柜、幻想/科幻收纳结构等；容器可以再打开 1～3 层子容器。
- 房间内的“私人终端”在现代设定表现为私人手机；非现代世界可适配为私人通讯终端/传讯器。内容按泛化的消息、相册、便签、日历、浏览/收藏/联系人等分区展示，不复制真实商业 App UI。
- 物品/手机中凡明确声称“User 与 Char 过去共同发生过”的内容，仍必须经过 `sourceMemoryIds + sourceMemoryAnchor` 校验；纯角色设定推导会标记为“生活设定”，不能伪装成共同历史。

## 0.8.8 档案室与后台任务

- 打开“档案室”先进入**全角色档案库**：只显示已经建立过心跳回忆档案的角色；点进角色后再按聊天窗口查看各自独立的档案名称。
- 新档案会自动写入轻量全局索引；旧版本档案可手动点“扫描旧版本已有档案”迁移。该重扫描不会在日常切聊天时自动执行。
- 建档前增加**扫描记忆 / 摘要**步骤：被动读取当前提示注入摘要与当前聊天 metadata 摘要；只有用户另外开启第三方公开 reader 授权时，才会调用 `getInjectedHistory()` / 其它 current-chat reader / `getSnapshot()`，并显示实际读取来源、条数和字符量，再允许创建/更新档案。
- `getSnapshot()` 与 `getInjectedHistory()` 会合并读取；外部记忆扩大到最多 256 条 / 24 万字符并分块整理，避免只吃到当前注入的少量记忆。
- 生成任务不再因为切换聊天窗口而主动 abort。结果始终绑定发起时的角色、chatId 和 archiveRevision；若完成时原窗口不在前台，会暂存并在回到原窗口后自动写回。

## 记忆相关世界书（r19）

“扫描记忆 / 摘要”旁新增 **选择记忆相关世界书**。这是给“记忆插件的摘要/条目需要另一本文档解释人名、地点、组织、术语或关系背景”的情况用的。

- 可以勾选某本世界书 **整本导入**。
- 也可以展开世界书，精确勾选具体 UID 条目。
- 选择按**当前聊天**保存在 chat metadata 中，只保存世界书名称、整本/精确模式和 UID 列表，不复制世界书全文，也不修改世界书。
- 真正读取只发生在用户显式点击“扫描记忆 / 摘要”时，通过 SillyTavern 公开 `getWorldInfoNames()` / `loadWorldInfo()` 读取。
- 这些世界书内容只会与记忆/摘要一起作为**解释上下文**发送：它能帮助模型理解摘要里的“他/那个地方/某组织”指什么，但**不能单独制造已经发生的回忆，也不能充当 sourceExternalId / sourceExternalAnchor**。事实仍必须锚定当前聊天记忆/摘要本身。
- 普通未选择的世界书继续只是设定上下文。整本/精确导入总计最多 8 本、160 条、52,000 字符，避免挤爆外部记忆请求。

如果你只选择了记忆世界书、但当前没有任何可读的记忆/摘要，世界书不会单独生成档案事实；它只是等待以后配合真正的记忆/摘要使用。

## 当前窗口记忆 / 摘要兼容（r11）

建档时的补充资料不再绑定单一记忆插件。插件会按顺序尝试：

1. 能明确表示“当前聊天”的公开 API（`getInjectedHistory`、`getCurrentChatMemories`、`getCurrentChatMemory`、`getCurrentChatSummary`、`getCurrentSummary`）；
2. 当前 SillyTavern prompt 中明确标为 memory / summary / 摘要 / 总结的注入文本；
3. 当前聊天 `chatMetadata` 中明确标为摘要/记忆的数据。

所有补充资料都要经过 externalId + 原文 anchor 校验。世界书、角色卡、作者注记属于设定上下文，不作为“某件事已经发生”的证据；原始当前聊天正文仍是最可靠的事实来源。

### r13: incremental archives and read-only archive browsing

- “更新当前窗口档案” is incremental by default: it only processes chat messages added after the previous archive plus changed current-chat memory/summary sources. Existing Mxxx IDs and generated Album/CG/ADV/Room/Ending/Items/Phone content are retained.
- If an already archived message was edited/deleted/reordered, the incremental update stops. Use the separate “完全重建档案” only when you intentionally want a full rescan and are willing to invalidate derived content.
- ADV bulk generation no longer auto-retries every failure individually. After a partial failure, choose either one more bulk request or an explicitly confirmed per-item repair pass.
- Opening another character/chat archive from the archive library is read-only and does not switch the SillyTavern chat. Generated content can be viewed from saved metadata; mutation/generation actions remain disabled until you intentionally return to that chat.
