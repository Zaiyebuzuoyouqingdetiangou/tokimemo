世界书边界
- 所有权使用已有角色 avatar 作用域；新增条目设置宿主 characterFilter，模型生成的正文不参与授予条目归属或写目标权限。
- 角色级队列外加全局 Symbol 书名队列，包含读取、复制、修改、保存和新建绑定；不同角色及 bootstrap/runtime 副本共享同一本书的锁。
- 已有主书 null、缺失 entries、数组 entries 均停止，不伪造空书覆盖；宿主返回对象先克隆，保存失败不通过引用污染宿主缓存。
- 老条目仅在保存回执、完整正文、hash 与唯一绑定或明确独占 filter 均满足时认领；排除、多人、tag、空 filter 与归属不明条目保留。
- 异步阶段重查角色身份与原主书；新建绑定迟到后不以本地赋值覆盖用户的新主书选择。移除使用原 lore.book，不改为当前新选择的书。
- 未修改 loreState 的 stale 条件，旧回执不因缺少 owner 自动触发启动迁移扫描。

音源边界
- 只对明确 unsaved 的本页临时状态放宽更换/移除；已知持久音源、读到持久行、新收到的持久回执均保旧。
- 每个 key 记录尚未完成回执的存储操作；旧写已提交但回执迟到，且后续读写同时失败时，不允许临时 fallback 覆盖或移除它。
- 原操作序号、AbortController、isCurrent、已提交结果权威和 URL 回收路径保留；没有增加远端请求、付费生成、模型输入、凭证处理或 HTML 执行入口。

独立发现并在本轮解决
1. 已绑定世界书读回 null 可能当空书覆盖原有用户条目，或移除时清掉本地回执。用独立执行复现后已改为失败保旧。
2. 新建书绑定回执迟到时，本地赋值可能覆盖用户刚选择的另一主书。用独立执行复现后已增加回执后的选择检查。
3. 新建 null 分支可跳过缺失的刷新 API 而相信旧书名列表。提出后已要求刷新与列表 API 均存在；最终独立执行得到 RMT_STICKER_LORE_READ，保存次数为 0。
4. 音源旧物理提交回执迟到 + 后续读写都失败的组合可能被临时 fallback 越过。与实现代理讨论后增加 unsettledStorage 保护，并验证组合回归通过。
