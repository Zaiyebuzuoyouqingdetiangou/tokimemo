## 二、硬约束

- 重构期间**功能零改动**：界面、按钮、生成结果、提示词逐字不变；用户存档完全兼容。
- 运行包对外 5 个导出和 `index.js` 启动层不变。
- 自制打包器只认单行 `import * as X from '…'` / `import { a, b } from '…'`，导出只认 `export function`、`export async function`、`export const`。
- 新增 / 拆分模块不用再手改 `tools/runtime-module-order.json`。构建脚本按初始化时会读到的导入自动排序（r84.121）。命名导入在初始化时取值，这种边要是成了圈，构建会停住。

- 测试不能删、不能改预期、不能放宽来凑全绿。

## 六、做完怎么测

每一项做完都跑下面全部命令，结果写进交付报告：

```bash
node tools/build-runtime-bundle.mjs .                          # 连续跑两次，输出的 sha256 必须一样
node --experimental-vm-modules --test tools/test-*.mjs         # 全部测试全过（r84.123 实测 228/228）
node --experimental-vm-modules tools/verify-runtime.mjs        # 语法 + 初始化绑定：undefinedBindings 与 prematureReads 必须是 0
node --experimental-vm-modules tools/refactor-guard.mjs check  # 代码文字 / 导出 / CSS / 加载顺序与基线一致
node tools/check-undefined-names.mjs                           # “用了没定义”扫描为 0（r84.94 实测 0）
```

判定标准：

- **原样搬家类**（split-module / split-dispatch）：护栏 check 必须 ok；拼回原文的对照测试逐字相同。
- **改写类**（4-B、4-C）：先写对照测试，改前改后结果一致；护栏里被改写的函数逐条登记在 `verification/refactor-allow.json` 并写原因。
- **动到界面的**：交付报告里列出要用户手点的页面。常用手点清单：
  - 主窗口打开 / 关闭 / 返回，任务中心打开。
  - 设置页每个分区改一个选项，确认能保存。
  - 档案室：进角色页；建档或继续一次建档。
  - 各玩法生成一次：房间、HEART、私人终端、日历、关系、相簿、ADV 翻页。
  - 生一张 CG 图。
