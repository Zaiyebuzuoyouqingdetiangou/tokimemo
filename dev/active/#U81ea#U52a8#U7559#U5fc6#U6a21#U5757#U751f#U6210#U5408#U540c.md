# 自动留忆模块生成合同

> 本文只回答“抽中一个模块后，按什么顺序生成、何时才算完成”。  
> 产品逻辑见 [自动留忆与成就存档方案.md](./自动留忆与成就存档方案.md)，施工顺序见 [自动留忆实施清单.md](./自动留忆实施清单.md)。

## 1. 强制合同

### 1.1 完成单位

一次自动抽签对应一份**本轮模块完整成果**和一个成就。

- 目录、索引、结构草稿、plan 都只是中间状态。
- 第一步完成后，调度器必须自动继续后续步骤，不要求用户再点击。
- 抽签时冻结本轮有限计划，任务中途出现的新聊天留到下个周期。
- 本轮必需步骤全部完成前，只显示“回忆生成中”。
- 整体完成并保存后，才出现信封并解锁一个成就。
- 当前任务未结束时，不开始下一轮抽签。

### 1.2 请求计数

本文数字是正常成功路径中的文本生成 HTTP 请求数，不包含：

- 前置增量建档；
- 自动生图；
- 空响应、坏 JSON 等异常重试；
- 用户主动重新生成；
- 用户确认后的成就修复。

一次 `requestValidatedSegment()` 正常成功调用计为一次请求。并发只缩短时间，不减少请求数。

### 1.3 通用生成顺序

```text
周期到期
→ 增量建档
→ 没有新 Mxxx：noop，结束
→ 过滤候选并抽签
→ 持久化抽签票据
→ 创建并冻结 ModulePlan
→ 持久化完整步骤列表
→ 依次或受控并发执行未完成步骤
→ 每步校验并保存恢复点
→ 最后一个生成响应携带 achievement
→ 校验模块整体完整性
→ 原子保存成果、成就、揭晓记录
→ 显示 Toast 与信封
→ 计算下一周期
```

若中断：

```text
读取同一 drawId 和 ModulePlan
→ 跳过已成功且已保存的步骤
→ 只补 pending / failed 步骤
→ 不重新抽签
→ 不重跑已成功正文
```

### 1.4 最后响应

模块最后一个必需文本请求同时返回独立的成就末包。若模块正文完整但成就字段校验失败：

- 保存模块成果；
- 标记 `achievement_pending`；
- 不显示完整揭晓信封；
- 不自动重跑正文；
- 仅在用户确认后发送一次小型成就修复请求。

## 2. 前置建档

### 2.1 自动周期增量建档

```text
聊天增量分段
→ 必要时处理已变化的外部记忆分段
→ 合并并保存新 Mxxx
→ 输出 sourceMemoryIds
```

正常请求数近似为：

```text
Cchat + Cexternal
Cchat ≈ ceil(新增聊天字符数 / 30000)
Cexternal ≈ ceil(需重扫外部记忆字符数 / 26000)
```

5～10 楼短增量且外部来源未变化时通常为一次。没有新增 Mxxx 时，不进入任何模块生成链。

### 2.2 第一次建档

```text
聊天分段
→ 外部记忆分段
→ 合并档案
→ 最终档案简介（通常 0～1 次）
```

长聊天可能分成多个可恢复批次。建档请求数与首次模块队列请求数分别展示。

## 3. 模块总表

变量：

- `U`：本轮需要评论的已解锁相簿条目数；
- `E`：本轮 ADV 索引中的事件数；
- `S`：房间待补文字槽位数；
- `A`：电话 App 数或结局可用路线数；
- `M`：本轮需要更新的电话 App 数；
- `B`：蝴蝶效应分支轴数量；
- `D`：前世今生卷宗数量；
- `P`：可选正文补段，取 0 或 1；
- `C`：可选告白扫描，取 0 或 1。

| 模块 | 正常请求数 | 完成条件 | 自动开放建议 |
| --- | ---: | --- | --- |
| Album | `2 + ceil(U / 3)` | 索引、关系快照、全部已解锁条目评论 | 第二批 |
| ADV | `1 + ceil(E / 6)` | 索引中的全部事件正文 | 第四批 |
| Room | `1 + ceil(S / 6) + 0～2` | 结构及全部必需文字槽位 | 第二批后 |
| Items | 通常 2 | 结构及全部必需台词 | 第二批，依赖 Room |
| Phone | 首次 `1 + A`；增量 `1 + M` | 目录中全部计划 App | 第三批 |
| Inbox | `0～1` | 有计划时，本轮信件全部完成 | 第一批 |
| Cabinet | 1 | 本轮成果通过校验 | 第一批 |
| Travel | 1～2 | 地图／结构及要求正文 | 第二批 |
| Ending | 首次 `1 + A + C` | 目录中全部可用路线及扫描 | 第四批 |
| Calendar | 1 | 本轮成果通过校验 | 第一批 |
| Relations | 1 | 本轮成果通过校验 | 第一批 |
| Heart | 约 8～13 以上 | 冻结计划中的全部互动内容 | 最后开放 |
| Butterfly | `2 + B + P`，约 3～11 | MAIN、全部分支、Ω、要求正文 | 第四批 |
| Past Lives | `2 + D + P`，约 3～9 | 引子、全部卷宗、今生回响与落款 | 第四批 |
| Theme Song | 每首 1 | 一首完整歌曲 | 第二批，先补自动 plan |
| Bedtime | 每章 1 | 一章完整故事 | 第二批，先定新篇／续章规则 |
| Time Echo | 每篇 1 | 一篇完整回声 | 第二批，先补自动入口 |
| Achievements | 不作为模块 | 成就是其他模块末包 | 移出抽签池 |

## 4. 逐模块生成顺序

### 4.1 回忆相簿 Album

```text
1. 生成本轮 CG／相簿条目索引
2. 生成当前关系快照
3. 将全部已解锁条目按每批最多 3 条生成评论
4. 最后一个评论批次携带成就末包
5. 校验所有已解锁条目均达到可读要求
```

只有索引不算完成。`U = 0` 时不得伪造相簿成果；应按模块合同判定 noop 或另行定义无评论的完整情况。

### 4.2 ADV

```text
1. 生成本轮事件索引并冻结 E
2. 将索引中的全部事件按每批最多 6 篇生成正文
3. 最后一个正文批次携带成就末包
4. 校验 E 个事件均有完整正文
```

不能停在事件标题，也不能只挑一篇。人工单篇补写不属于自动完整链。

### 4.3 房间 Room

```text
1. 生成房间结构
2. 计算缺失文字槽位 S
3. 按每批最多 6 个槽位补全
4. 执行合同允许的质量修复
5. 最后一个必需请求携带成就末包
```

进入自动池前必须定义修复请求上限和确定性完成判据；达到上限仍不完整时保留恢复状态，不得误揭晓。

### 4.4 物品 Items

```text
前置：Room 已存在且版本匹配
1. 生成物品结构
2. 生成全部必需台词／描述
3. 第二步携带成就末包
```

若 Room 前置条件不满足，本轮不应把 Items 放入候选池。

### 4.5 电话 Phone

首次：

```text
1. 生成 App 目录并冻结 A
2. 按目录逐个或受控并发生成全部 A 个 App
3. 最后一个 App 响应携带成就末包
4. 校验目录内 App 全部完成
```

增量：

```text
1. 生成更新计划并冻结 M
2. 完成全部 M 个 App 更新
3. 最后一个更新响应携带成就末包
```

一个 App 完成后自动继续下一个。目录本身永远不生成成就。

### 4.6 收件箱 Inbox

```text
1. 规划并生成本轮全部信件，同时返回成就末包
```

计划为空时为 noop，不生成信封或成就。

### 4.7 陈列柜 Cabinet

```text
1. 生成／刷新本轮陈列柜成果及成就末包
```

### 4.8 旅行 Travel

```text
1. 生成地图／旅行结构
2. 若计划要求正文，继续生成全部正文并携带成就末包
```

若第一步已经是合同定义的完整成果，则成就放在第一步；否则结构不能提前揭晓。

### 4.9 结局 Ending

```text
1. 生成路线目录并冻结全部可用路线 A
2. 自动生成目录中的全部 A 条路线正文
3. 必要时执行一次告白扫描 C
4. 最后一个实际请求携带成就末包
5. 校验全部可用路线完成
```

不能为控制费用只生成一条路线。费用跨度应在模块介绍和确认页中明确展示。

### 4.10 日历 Calendar

```text
1. 生成／刷新本轮日历成果及成就末包
```

### 4.11 关系 Relations

```text
1. 生成／刷新本轮关系成果及成就末包
```

### 4.12 角色互动 Heart

当前代码没有稳定的模块整体自动计划，因此接入前先新增 plan。建议计划显式列出：

```text
1. 基础／时期对话
2. 日常一格
3. 萤火虫
4. 后日谈
5. 春季 Voice 与计划要求的 Scenario
6. 夏季 Voice 与计划要求的 Scenario
7. 秋季 Voice 与计划要求的 Scenario
8. 冬季 Voice 与计划要求的 Scenario
9. 最后一个计划步骤携带成就末包
```

计划中列出的内容必须全部跑完。不得在后台把它们偷偷拆成多个成就；若未来要拆，必须先在用户界面中正式成为可分别勾选的模块。

### 4.13 蝴蝶效应 Butterfly

首次：

```text
1. 生成 MAIN，并冻结分支轴 B
2. 生成全部 B 个分支
3. 生成唯一 Ω
4. 必要时补完整正文 P
5. 最后一个实际请求携带成就末包
```

增量：

```text
1. 生成本轮全部新增分歧与 Ω
2. 必要时补正文
3. 最后一个实际请求携带成就末包
```

首次生成可先保留给手动／首次队列，已有 session 的增量自动生成先开放。

### 4.14 前世今生 Past Lives

```text
1. 生成 episode 计划和引子
2. 若引子正文待补，完成引子正文 P
3. 生成全部 D 份卷宗
4. 生成今生回响与落款，同时携带成就末包
5. 校验整篇 episode 完整
```

每次生成一篇新 episode，不把它伪装成普通档案差量。

### 4.15 主题曲 Theme Song

```text
1. 生成一首完整歌曲及成就末包
```

当前自动入口会 noop；必须先补默认自动 plan 才能开放。

### 4.16 睡前故事 Bedtime

```text
1. 根据冻结计划生成一章完整故事及成就末包
```

自动 plan 必须明确是新故事还是指定 `storyId` 的续章。不能在运行时临时猜测。

### 4.17 时光回声 Time Echo

```text
1. 生成一篇完整回声及成就末包
```

当前不在旧自动列表，需补自动入口。

### 4.18 成就 Achievements

Achievements 不再是可抽模块，也不独立自动调用一次 API。

```text
模块最后一个必需生成响应
→ achievement 独立字段校验
→ 与模块成果共同提交
```

## 5. ModulePlan 最小结构

```ts
type ModuleStep = {
  id: string;
  kind: string;
  order: number;
  status: 'pending' | 'running' | 'completed' | 'failed';
  recoverySlot: string;
};

type ModulePlan = {
  version: 1;
  drawId: string;
  moduleId: string;
  chatId: string;
  archiveRevision: string;
  sourceMemoryIds: string[];
  expectedRequestRange: { min: number; max: number | null };
  steps: ModuleStep[];
  frozenAt: number;
};
```

要求：

- 首个目录／plan 响应后立即补全并保存 `steps`。
- 已完成步骤必须有可验证的恢复槽位。
- `pendingSteps()` 只返回未完成的必需步骤。
- `isComplete()` 同时检查计划步骤、模块数据和成就状态。
- 模块写入必须校验 `chatId`、人物名单与 `archiveRevision`。

## 6. 自动开放门槛

模块只有同时满足以下条件才能标记为 `autoEligible`：

- 有明确的有限 `ModulePlan`；
- 目录能转换为完整步骤列表；
- 可从任意已保存步骤恢复；
- 有确定性的 `isComplete()`；
- 最后请求已支持成就末包；
- noop 不会生成信封或成就；
- 请求范围能在界面解释；
- 酒馆和 TT 均通过中断恢复测试。
