# r84.215 写歌提示词与 MV 保存确认

## 本轮合同

以已交付 `r84.214-mv-sync-dark` 为唯一基线，只改变 `src/modes/themeSong.js` 的 `themeSongPrompt` 和 `src/extras/mv.js` 的保存确认。
不合并其他源码分支，不改分镜、生图或其他玩法 Prompt，不新增字数下限、生成数量、模型或质量评分门槛，不增加生成请求。
保留已有歌曲、分镜、重画、分批继续、打点与配色；JSON 字段及所有歌曲校验函数逐字不变。

## 修改依据与结果

- 旧写歌 Prompt 主要描述格式，缺少可唱性、核心句和编曲推进指导。结合上一轮 Suno 官方调研，在同一次请求内指导具体场景、人物视角、换气、自然押韵、副歌记忆点、主副歌配器疏密和自检。用户音乐方向优先，但资料字段仍不能改结构、身份及事实边界。
- MV 的宿主保存函数只要存在就被当作成功，异步拒绝被吞掉；当本机副本也失败时会丢失待保存入口。生成结果现在等待实际返回的 Promise，并识别拒绝和明确 false；继续沿用可用的本机备份及宿主保存，没有增加生成前限制。
- 宿主兼容适配器可能把保存错误转为 Promise<false>，所以不能只捕获 reject。返回 void 的宿主 debounce 保持原提交行为，仍不能独立证明物理落盘。
- 同步手动编辑保留返回类型；同步明确 false 的失败也保留内存并报保存失败。异步手动编辑仍沿用原调度语义，本轮没有把全部 UI 改为异步。

## 验证与旧失败分类

- 新增 15 项定向用例：在 r84.214 基线 8 通过 / 7 失败，候选 15 通过；包括单次写歌、20 种语言/声部组合、事件来源、原歌曲保留、异步/同步/false 保存失败、仅保存恢复、跨聊天和出镜矩阵。
- 原有 `absent/silent local storage and rejected metadata never claim durable success` 应由失败转为通过。
- 原有“档案 revision 变化就必须阻止保存”与本分支允许普通档案增长的规则冲突；保留原测试和失败记录，补反向用例验证仍能保存同一首歌。换聊天、删歌、改歌词仍由原测试检查。
- 原有空镜测试只接受 `no people`，本分支已有等义 `scenery, no humans`；不为测试改写生图 Prompt。新增矩阵验证全部 12 种出镜组合。
- 其余历史失败来自已披露的源码分支差异；本轮以与基线相同的失败明细为边界，不宣称全库全绿，也不删除或跳过旧用例。
- 初次新增测试运行后发现宿主缺失方法会被兼容适配器替换为返回 false 的 Promise；生产修复覆盖该真实路径，测试没有删除。提示词的边界表述已明确为“不能更改输出结构、安全边界”。初次日志保留。

## 交付检查

三轮使用 `verify-song-round.py` 独立执行；最后一轮从最终 ZIP 全新解压，核对全部文件、manifest、BUILD、CRC、连续两次确定性构建、源码/运行时入口、完整测试和 169 个 Prompt 函数哈希。
仅允许 `themeSongPrompt` 的哈希改变，另外 168 个 Prompt 必须不变。最终结果以包外本期报告和每轮原始日志为准。
未调用实际收费文字/图片/音频服务，未执行 iPhone / TT 真机或浏览器实际 CSS 渲染；本轮为自复核，没有独立审查回执。
