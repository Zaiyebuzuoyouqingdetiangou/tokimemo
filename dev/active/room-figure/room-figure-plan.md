# 房间 Q 版小人按人设显示（room-figure）

用户原话（2026-09-25，附截图 方祁洛·后院空场）：“Q版小人好像所有的人都长一个样，我是想让他按人设生成的。”

## 现状（r84.73 代码核对）

- 小人由 `ui/roomPixelFigure.js` 用固定像素块画出，只读 4 个字段：发色 `hairTone`、发型 `hairShape`、衣着 `outfit`、体型 `build`。
- 这 4 个字段来自房间生成时模型填写的 `visualProfile.figure`，但每个字段都必须在角色卡 / 世界书里找到**逐字原文**，并且通过 `modes/roomProfile.js` 里 `roomVisualEvidenceSupports` 的窄正则（例如衣着只认“古装 / 长袍 / 汉服 / 和服 / 道袍”）。不通过就回落为 `unspecified`。
- `unspecified` 的衣服是同一种灰紫色，头发是同一种暗色。所以大多数角色最后画出来一样（截图里就是灰紫衣服）。
- 已有的 `detail`（眼镜、尖耳、兽耳、角、头饰、围巾、护目镜、耳机）和 `posture` 字段，像素小人根本没画。
- `hairShape` 的 cropped / medium / covered / nonhuman 在像素小人里和默认几乎没区别。

## 方案（待用户确认第 3 点）

1. 小人把已有字段都画出来：配饰（眼镜、尖耳、兽耳、角、头饰、围巾、护目镜、耳机）、更多发型区别；黑发 / 白发与深色 / 银色分开。只改代码画法，不接受模型给的颜色、坐标或 SVG。
2. 扩大“角色卡写明”的识别写法：衣着认 玄衣 / 黑袍 / 锦袍 / 长衫 / 襦裙 / 白衣 / 西服 等，发色认 墨发 / 玄发 / 乌发 / 雪发 等；仍要求角色卡或世界书里真的写了。
3. 旧房间：打开时在本地按当前角色卡重新识别小人外形（不请求模型、不改房间其他内容、不写回存档）。
4. **待定**：角色卡没写外貌时，是否允许按身份推断（例如修仙 / 古风角色默认长袍、现代角色默认便服）。项目原则一直是“没有依据不虚构人物外形”，这一条需要用户明确授权才做。

## 验证

像素小人对每个字段组合做快照测试；识别写法逐条正反例测试；旧房间打开不产生任何模型请求；refactor-guard 对本任务改动的声明逐条登记在 `verification/refactor-allow.json`。
