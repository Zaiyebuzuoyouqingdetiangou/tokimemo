# 自动留忆：当前逻辑与排查标识

写到 0.99.20 / r84.65。本文描述代码现在实际怎么跑。控制台里搜 `AM-` 就能对上下面的标识。

## 排查标识

这些字符串会出现在浏览器控制台，前缀是 `[HeartbeatMemories]`。

| 标识 | 意思 |
| --- | --- |
| `AM-arm` | 第一次看见楼层，只记下一次到期点，这一轮不抽 |
| `AM-wait` | 间隔还没到 |
| `AM-queued` | 上一份还没补完，新的间隔排在后面，不另抽 |
| `AM-hold` | 这一份还在写，间隔还没到，接着原来的票 |
| `AM-drawn` | 抽中了，这一轮已经写上 |
| `AM-reuse` | 接着上一张还开着的票 |
| `AM-noop` | 这一窗没有新的档案编号，不生成 |
| `AM-failed` | 这一次没写完。任务中心可以点「补全这一抽」 |
| `AM-reveal` | 回忆和成就都在，这一份算完成，成就已进库 |
| `AM-saved` | 正文步骤记下了，整份可能还没结束 |
| `AM-ACH-REPAIR` | 补全时只补缺少的成就，不重写正文、不另抽。出现在成就修复提示词里 |

正文还在生成时不会打出开抽标识。主楼生成看酒馆的 `GENERATION_STARTED` / `GENERATION_ENDED`、停止按钮和流式状态。插件自己的副 API 在这之后才发。

## 一轮实际怎么走

计划存在当前聊天的 metadata（`autoMemoryPlanV1`）。IndexedDB `heartbeat_memories_auto_memory_v1` 只做恢复备份和租约，不能覆盖更新的 metadata。间隔只数角色楼，用户楼和系统楼不算。设置里没有「只数角色楼」的开关，这一条是固定的。

1. 向导保存后 `enabled` 为真。成就库不进抽签。
2. 第一次看见楼层只记账：`nextDueFloor = 当前角色楼 + 间隔`。标识 `AM-arm`。
3. 最新一条角色楼的正文要等 API 调用结束并停稳，才允许到点。流式输出、只有省略号、或停止按钮还在时，不建档、不抽签。
4. 到点后的顺序：增量建档这一窗 → 没有新 `Mxxx` 则 `AM-noop` → 有新编号才抽签。抽中的模块按冻住的计划生成。没生成过的按第一次生成。
5. 一份是「当前回忆 + 当前成就」。成就写在这一抽的第一次文本请求里，和回忆同一份 JSON。两样都校验通过才揭晓，成就写入成就库，`origin` 为 `auto`，并记下当时那条角色楼的 mesid。库里点「回到当时」跳到那一楼。手动成就没有这个按钮。
6. 正文留下了、成就没通过：状态 `achievement_pending`。补全只再发一次成就修复（提示词里有 `AM-ACH-REPAIR`），不重跑正文，不另抽。
7. 没写完就到了下一间隔：不放弃、不另抽，标识 `AM-queued`。用户点「补全这一抽」只补当前这张票。这一份真正结束后，才按已经过去的角色楼窗抽一次。中途又过了几档，也只抽这一次，不连抽。
8. 设置里的「失败后自动重试」仍作用在同一张票上，次数 1 到 5。信上和任务中心没有「重试」按钮。设置里的「按原签再写 / 重新抽一份 / 自己选一份」是用户主动换写法，不是补全。

抽签池按代码里的注册表：除成就库外，已注册模块都在池里。物品需要已有房间。

## 页面上会看到什么

| 时机 | 楼层下面 | 标识 |
| --- | --- | --- |
| 计划没开，或档案没好 | 没有壳 | 无 |
| 第一次记账 | 倒计时 | `AM-arm` |
| 还没到间隔 | 倒计时 | `AM-wait` |
| 上一份还在补，新间隔到了 | 任务中心写着排在后面 | `AM-queued` |
| 这一份还在写 | 信封拆不开 | `AM-hold` |
| 抽中并写完 | 爱心信。成就进库，可回到当时那条角色楼 | `AM-drawn` 或 `AM-reveal` |
| 没有新编号 | 不生成 | `AM-noop` |
| 没写完 | 任务中心只有「补全这一抽」 | `AM-failed` |
| 正文在、成就缺 | 补全只补成就 | `AM-ACH-REPAIR` |
| 原生群聊 | 不跑 | 只支持单角色聊天，每个群提示一次 |

设置里「自动留忆」是一级卡片，排在独立 API 后面，不收进「更多设置」。信封样式的预览和六个选项都是小图。

## 还留着的边界

- 摘要指纹一变，可能把整份外部摘要送去建档。摘要没写到的楼会另附完整正文。
- 两个页面同时开时，网页锁优先；没有网页锁才用大约 20 秒的租约。
- 向导没排除的模块都会进池。旧计划如果排除名单是空的，到点会抽全部已注册模块。
- 群聊不跑，每个群提示一次。
- 出信那一楼的正文没了，这一轮的回忆和自动成就一起收走。跳不到楼时，成就卡片还在。

- **没排除就会进池。** 向导默认全选。取消勾选才会排除。旧计划如果只写了偏好、排除名单仍是空的，到点仍会抽所有未排除模块；在向导里重新保存一次勾选后，取消的项才会真正不抽。
- **摘要没写楼号时，这一窗正文会整段再送一次。** 摘要点了名的楼不再附正文。摘要记录里没有楼号时，没法知道缺了哪几楼，这一窗正文会完整附上，费用会比只送摘要更高。
- **角色楼是固定规则。** 间隔只数角色楼。用户楼和系统楼不算，设置里不能改回按全部消息计数。
- **没有新编号就停。** 摘要或正文送进去了，但合并后没有新的 `Mxxx`（重复、空抽取、或自动建档被未完成的私人终端草稿挡住），这一轮不抽签、不生成。倒计时进入下一个间隔，旁边会说明，并可以点「补」再问一次。模型仍认为没有可补的经历时，不再发请求，倒计时留在下一间隔。
- **第一次生成不是零请求。** 没生成过且增量数量为 0 的模块，会先做一次目录步骤，而不是直接跳过。目录长不出来才放开这张票据。
- **两个页面。** 网页锁优先。没有网页锁才用 IndexedDB 租约，有效约 20 秒，约 8 秒续一次，绑定 `chatId`、`dueFloor`、`archiveRevision`。两种锁都没有时，只靠本页的进行中标记，挡不住另一个标签页。
- **接管只跳过「全部步骤都已完成」。** 做到一半时，接管会接着原来的票据，不会新抽一张。若完成状态还没写入 metadata，接管仍可能把这一窗再送去建档。
- **楼层编号。** 「回到当时」优先用自动留忆出信那一楼（mesid）。没有出信楼层时，才用档案记忆上的 `messageStart` / `messageEnd`，并要求落在覆盖范围内。模型写了覆盖范围外的楼层会被丢掉。覆盖范围还是空的旧档，会相信记忆上的楼层号。按钮上印的是聊天里的 `#`，也就是 mesid。
- **群聊不支持。** 打开群聊不会自动留忆，每个群提示一次。楼层上不挂信，也不当成生成失败。一张卡里的多人物仍走原来的世界书人选。
- **正文要停稳。** 流式开始、流式 token、生成中标记、停止按钮、消息上的 streaming 类，或正文还是省略号，都不会开跑。token 停住、正文也不再是占位之后，才按间隔建档。宿主若完全不发这些事件，又把占位正文换成完整正文却不通知页面，要等下一次聊天事件才会接着跑。
