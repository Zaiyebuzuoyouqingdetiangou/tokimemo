## 一轮实际怎么走

计划存在当前聊天的 metadata（`autoMemoryPlanV1`）。IndexedDB `heartbeat_memories_auto_memory_v1` 只做恢复备份和租约，不能覆盖更新的 metadata。

1. 向导保存后 `enabled` 为真，这条聊天的旧自动更新暂停。成就库不进抽签。
2. 第一次看见楼层只记账：`nextDueFloor = 当前楼层 + 间隔`，不建档，也不生成。
3. 档案已经写好、又没在建档时，最新一条角色楼层下面显示倒计时。「还差 N 楼」；只剩一楼或已经到点，写成「下一楼」。不悬浮，不挡住输入。档案没好，或正在建档，这个壳不出现。
4. `当前楼层 >= nextDueFloor` 时，顺序固定为三步：
   - **增量建档。** 窗口是上次完成的下一楼到当前楼。记忆插件有新摘要时，用摘要写入档案，不把这一窗正文再强制送一遍。摘要没更新，才读这一窗正文。不改用户保存的读取范围。
   - **抽签。** 建档后出现新的 `Mxxx` 才抽。没有新编号就结束这一轮，不发模块请求。
   - **增量回忆。** 抽中的模块按冻住的计划生成。没生成过的按第一次生成。楼层下只展开这一轮新增内容。
5. 票据和计划先写入聊天，再发模块请求。刷新后只补没做完的步骤。最后一步才带成就。成就没通过就留下待补，不重跑正文。
6. 整份计划完成前，不显示「获得了成就」。完成后是「谁获得了哪一段的成就，点击查看详情」。

抽签池是：注册表里可自动生成、成就已并入、前置满足的模块，去掉用户排除的。物品需要已有且版本匹配的房间。向导里取消勾选就是排除；没有排除名单时，这些模块都会进池。

记忆插件指这三处已有摘要：SillyTavern Memory（`1_memory`）、柏宝书、千千结。世界书变动不算这份摘要。摘要「有更新」是指和档案里上次记下的外部指纹不同，并且摘要条数大于 0。

## 页面上会看到什么

| 时机 | 楼层下面 | 提示 |
| --- | --- | --- |
| 计划没开，或档案没好 | 没有壳 | 无 |
| 等待下一轮 | 「留忆 / 还差 N 楼」或「下一楼」 | 无 |
| 目录还没定 | 正在建立目录 | 无 |
| 步骤进行中 | 正在生成，步数已知才写 `已完成 / 总步数` | 无 |
| 整份完成 | 谁获得了哪一段的成就 | 「今天留下了新的回忆」 |
| 失败 | 已写的部分还在，不当成已拆开 | 「这份回忆停住了」 |
| 成就没写上 | 不拆开 | 「回忆先留着」 |
| 原生群聊 | 不跑 | 只支持单角色聊天，每个群提示一次 |

点开完成后的壳，只看这一轮新增的信、章节或条目。以前的内容用「以前的内容在插件里」。成就页里，档案能对上的经历标「当时」，可以「回到当时」并列出楼层。外部或继承的记录只说明来源，不跳转。跳不到楼层时，成就卡片还在。

## 怎么验收

先把测试分支更新进酒馆，确认版本是 `0.99.45-r84.97-memory-pace`。不要用主分支。向导里的生图和设置是同一套，配完点下一步。设置里可以改抽签间隔，也可以勾选只在最新角色楼生成。打开插件后，顶端会显示还要等几楼。

本地已覆盖的合同：

```bash
node --experimental-vm-modules --test tools/test-auto-memory-r*.mjs
node tools/verify-runtime.mjs
```

真机按这个顺序看。每条都要看结果，不要只看壳是否出现。

1. 没有档案时启用计划。继续聊天。楼层下不出现壳，也不出现「正在建档」。
2. 插件里建档完成后，楼层下出现倒计时。间隔 5 时，从记下的那一楼再聊，应依次看到还差 5、4、3、2 楼，然后是「下一楼」。
3. 到点后先看档案是否多了新 `Mxxx`，再看是否只生成一个模块。同一楼重复事件不能再请求一次。
4. 开着 SillyTavern Memory、柏宝书或千千结，并让摘要相对上次建档有变化。这一轮建档应走摘要，不应把同一窗正文再强制送一遍。把摘要停住再聊过间隔，才应改读正文。
5. 排除一个模块后再到点。票据里不能出现它。没排除、也从没生成过的模块，可以按第一次生成被抽中。
6. 生成中刷新、切换页面再回来。已完成的步骤不重做，未完成的步骤接着做。完成后才出现成就句。
7. 点楼层下的成就，只看到这一轮新增。插件里仍能看到旧内容。
8. 打开成就，对有楼层的历史成就点「回到当时」，聊天滚到对应楼并高亮。外部或继承的成就没有跳转按钮。跳不到时，成就正文仍能读。
9. 两个页面同时开同一聊天。有网页锁时只有一个页面在跑。没有网页锁时，另一个页面要等约 20 秒租约过期才能接管，且已完成步骤不重发。
10. 打开原生群聊。不自动留忆，并提示只支持单角色聊天。
11. 关掉计划。旧的按模块自动更新可以恢复，排除名单不要被清掉。

清单第 11 节的真机矩阵仍全部未勾。桌面、手机、TT、间隔 1 / 5 / 10 / 1000、长聊天、单人与多人、建档时继续聊、请求中刷新、切聊天，都要在上面的步骤之外再各走一遍。

## 优化方向

- 向导里取消勾选会写入排除名单，到点不会抽中。一项都没排除时，可自动生成的模块都会进池，向导里显示为全选。
- 摘要只带这一窗的新片段。现在指纹一变，会把整份变化了的外部摘要送去建档，可能重处理旧摘要。
- 摘要覆盖不完整时，补上摘要没写到的那几楼正文，而不是整窗二选一。柏宝书的注入口径明确不含最近正文。
- 到点但没有新 `Mxxx` 时，在倒计时旁说明这一轮没留下新档案，避免看起来像没触发。
- 租约心跳跟长请求绑在一起。生成超过 20 秒且页面卡住时，另一个页面可能接管。心跳应在请求进行中继续，或把租约延长到这一轮结束。
- 成就揭晓句目前用模块名。揭示记录里没有成就标题，不能在不改 schema 的情况下把模型写的标题存进去。
- 旧自动更新确认没有双调度后，再单独安排删除。不要和功能改动混在一次提交里。

## 潜在问题

- **没排除就会进池。** 向导默认全选。取消勾选才会排除。旧计划如果只写了偏好、排除名单仍是空的，到点仍会抽所有未排除模块；在向导里重新保存一次勾选后，取消的项才会真正不抽。
- **摘要路径可能漏掉这一窗正文。** 选择摘要时，不会把「上次完成之后的那几楼」强制送进建档。若插件摘要没包含这几楼，而这一轮又因为指纹变化走了摘要，这几楼不会在下一轮补读，因为窗口已经往前移了。
- **摘要路径仍可能带上增量正文。** 没强制替换窗口时，导入器原有的「基线之后的新消息」还在。摘要和这段新正文可能一起送出，费用不是严格的一次摘要。
- **没有新编号就停。** 摘要或正文送进去了，但合并后没有新的 `Mxxx`（重复、空抽取、或自动建档被未完成的私人终端草稿挡住），这一轮不抽签、不生成。倒计时会进入下一个间隔。
- **第一次生成不是零请求。** 没生成过且增量数量为 0 的模块，会先做一次目录步骤，而不是直接跳过。目录长不出来才放开这张票据。
- **两个页面。** 网页锁优先。没有网页锁才用 IndexedDB 租约，有效约 20 秒，约 8 秒续一次，绑定 `chatId`、`dueFloor`、`archiveRevision`。两种锁都没有时，只靠本页的进行中标记，挡不住另一个标签页。
- **接管只跳过「全部步骤都已完成」。** 做到一半时，接管会接着原来的票据，不会新抽一张。若完成状态还没写入 metadata，接管仍可能把这一窗再送去建档。
- **楼层编号。** 「回到当时」用档案记忆上的 `messageStart` / `messageEnd`，并要求落在覆盖范围内。模型写了覆盖范围外的楼层会被丢掉。覆盖范围还是空的旧档，会相信记忆上的楼层号。高亮用的是酒馆楼层序号减一，和消息正文里的楼层显示不一定是同一个数。
- **群聊。** `groupId` 仍直接拒绝。提示每个群、每次打开页面一次。这不是一张卡里的多人物；多人物仍走原来的世界书人选。
- **r84.91 的更新说明有一句旧顺序。** `CHANGELOG.md` 里 0.99.39 写着「做成增量回忆，然后抽签」。0.99.40 起的代码是先建档，再抽签，再生成回忆。以 0.99.40 和本文为准。
