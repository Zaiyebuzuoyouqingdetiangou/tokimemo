## 一轮实际怎么走

计划存在当前聊天的 metadata（`autoMemoryPlanV1`）。IndexedDB `heartbeat_memories_auto_memory_v1` 只做恢复备份和租约，不能覆盖更新的 metadata。

1. 向导保存后 `enabled` 为真，这条聊天的旧自动更新暂停。成就库不进抽签。
2. 第一次看见楼层只记账：`nextDueFloor = 当前楼层 + 间隔`，不建档，也不生成。
3. 档案已经写好、又没在建档时，最新一条角色楼里面显示倒计时。「还差 N 楼」；只剩一楼或已经到点，写成「下一楼」。壳是这条消息内部的节点，不是聊天容器旁边的兄弟节点。不悬浮，不挡住输入。插件顶端另有「回忆还有 N 楼」。勾选「只在最新角色楼生成」后，楼层下面和顶端用同一套角色楼计数。档案没好，或正在建档，这个壳不出现。
4. 最新一条角色楼的正文要停稳，才允许到点。流式输出、只有省略号、或停止按钮还在时，不建档、不抽签，也不把信挂到这一楼。停稳之后，顺序固定为三步：
   - **增量建档。** 窗口是上次完成的下一楼到当前楼。记忆插件有新摘要时，摘要和「摘要没写到的那几楼完整正文」一起送去建档。摘要没有楼号时，这一窗正文整段附上，不做截字。摘要没更新，才只读这一窗正文。不改用户保存的读取范围。
   - **抽签。** 建档后出现新的 `Mxxx` 才抽。没有新编号就结束这一轮，不发模块请求。倒计时进入下一间隔，旁边说明原因，并可以点「补」再问一次。
   - **增量回忆。** 抽中的模块按冻住的计划生成。没生成过的按第一次生成。完成后楼层上是一封爱心信。点开先看到「谁获得了哪一段的成就」，再点「打开这封回忆」，这一轮内容就在信里展开。
5. 票据和计划先写入聊天，再发模块请求。刷新后只补没做完的步骤。成就和第一次请求写在一起，分两次的模块不跟后面那次。通过后追加进成就库，手动成就留在库里。成就没通过就留下待补，不重跑正文。信上的「补成就」只再发一次成就请求。
6. 整份计划完成前，信上不写「获得了成就」。完成后先是一封未拆的爱心信，点开才出现「谁获得了哪一段的成就」，再点才在这封信里打开回忆。生成没写完时，信上有「重试」，已经写好的步骤留着。设置里勾上失败后自动重试，补成就和重试会按 1 到 5 次自己跑。抽签那一楼的正文被重 roll 后，按原来抽中的模块再写。设置里可以按原来的抽签再写、重新抽一份，或自己选一个模块。

抽签池是：注册表里可自动生成、成就已并入、前置满足的模块，去掉用户排除的。物品需要已有且版本匹配的房间。向导里取消勾选就是排除；没有排除名单时，这些模块都会进池。

记忆插件指这三处已有摘要：SillyTavern Memory（`1_memory`）、柏宝书、千千结。世界书变动不算这份摘要。摘要「有更新」是指和档案里上次记下的外部指纹不同，并且摘要条数大于 0。

## 页面上会看到什么

| 时机 | 楼层下面 | 提示 |
| --- | --- | --- |
| 计划没开，或档案没好 | 没有壳 | 无 |
| 等待下一轮 | 「留忆 / 还差 N 楼」或「下一楼」。没有新编号时旁边说明，并有「补」 | 无 |
| 目录还没定 | 爱心信：正在建立目录 | 无 |
| 步骤进行中 | 爱心信：正在生成，步数已知才写 `已完成 / 总步数` | 无 |
| 整份完成 | 爱心信。点开后是谁获得了哪一段的成就，再点在信里打开回忆 | 「今天留下了新的回忆」 |
| 失败或还没写完 | 爱心信上有「重试」。已写的部分还在 | 「这份回忆停住了」 |
| 成就没写上 | 信上有「补成就」，只发一次 | 「回忆先留着」 |
| 原生群聊 | 不跑 | 只支持单角色聊天，每个群提示一次 |

点开完成后的信，先看到成就句，再在这封信里看这一轮新增的信、章节或条目。成就页里，档案能对上的经历标「当时」，可以「回到当时」并列出楼层。外部或继承的记录只说明来源，不跳转。跳不到楼层时，成就卡片还在。

## 怎么验收

先把测试分支更新进酒馆，确认版本是 `0.99.77-r84.129-letter-repair`。成就没写上时，信上应有「补成就」，点一次只发一次请求。回忆没写完时有「重试」。勾上失败后自动重试后，这两件事会自己跑。抽签楼正文重 roll 后应按原来的模块再写。设置里可以按原来的抽签再写、重新抽一份，或自己选模块。每份回忆写完后，成就应出现在插件的成就库里，标成「自动」；手动生成的成就仍在。分两次请求的模块，成就跟第一次请求一起写。打开信封后，回忆应在信纸里上下排开，不要再从右边挤出去。信里只应出现这一轮新增的条目，点卡片或「走进共同回忆」应能在信里看到这一条。这一轮写完后，信上先是成就句。不要用主分支。向导里的生图和设置是同一套，配完点下一步。设置里可以改抽签间隔，也可以勾选只在最新角色楼生成。打开插件后，顶端会显示还要等几楼。最新楼还在输出时，楼层下面不该先出现信。正文停稳后才建档、抽签。摘要没写到的楼会带上完整正文。回到当时的楼号应和消息上印的 `#` 一致。群聊不自动留忆。完成后的入口应是爱心信，点开能在信里看到回忆，成就句用模型写下的标题。TT 上聊天虚拟化应保持开启。没有新编号时，倒计时旁应有说明和「补」。

本地已覆盖的合同：

```bash
node --experimental-vm-modules --test tools/test-auto-memory-r*.mjs
node tools/verify-runtime.mjs
```

真机按这个顺序看。每条都要看结果，不要只看壳是否出现。

1. 没有档案时启用计划。继续聊天。楼层下不出现壳，也不出现「正在建档」。
2. 插件里建档完成后，楼层下出现倒计时。间隔 5 时，从记下的那一楼再聊，应依次看到还差 5、4、3、2 楼，然后是「下一楼」。
3. 到点后先看档案是否多了新 `Mxxx`，再看是否只生成一个模块。同一楼重复事件不能再请求一次。
4. 开着 SillyTavern Memory、柏宝书或千千结，并让摘要相对上次建档有变化。这一轮建档应走摘要，不应把同一窗正文再强制送一遍。把摘要停住再聊过间隔，才应改读正文。
5. 排除一个模块后再到点。票据里不能出现它。没排除、也从没生成过的模块，可以按第一次生成被抽中。
6. 生成中刷新、切换页面再回来。已完成的步骤不重做，未完成的步骤接着做。完成后才出现成就句。
7. 点楼层下的成就，只看到这一轮新增。插件里仍能看到旧内容。
8. 打开成就，对有楼层的历史成就点「回到当时」，聊天滚到对应楼并高亮。外部或继承的成就没有跳转按钮。跳不到时，成就正文仍能读。
9. 两个页面同时开同一聊天。有网页锁时只有一个页面在跑。没有网页锁时，另一个页面要等约 20 秒租约过期才能接管，且已完成步骤不重发。
10. 打开原生群聊。不自动留忆，并提示只支持单角色聊天。
11. 关掉计划。设置里不再出现按模块楼层开关。排除名单不要被清掉。关闭后仍能手动生成。

清单第 11 节的真机矩阵仍全部未勾。桌面、手机、TT、间隔 1 / 5 / 10 / 1000、长聊天、单人与多人、建档时继续聊、请求中刷新、切聊天，都要在上面的步骤之外再各走一遍。

## 优化方向

还没改，留着：

- 摘要只带这一窗的新片段。现在指纹一变，会把整份变化了的外部摘要送去建档，可能重处理旧摘要。摘要没写到的楼会另附完整正文，但摘要本身仍可能是整份。
- 租约心跳跟长请求绑在一起。生成超过 20 秒且页面卡住时，另一个页面可能接管。心跳应在请求进行中继续，或把租约延长到这一轮结束。
- 旧自动更新确认没有双调度后，再单独安排删除。设置页上的按模块楼层规则已拿掉。计划关掉之后，旧引擎在后台仍可能接着跑，页面上不再提供那些开关。

已经落地，不必再当作待改：

- 向导取消勾选写入排除名单；一项都没排除时显示为全选。这是当前行为，不是缺口。旧计划若排除名单仍是空的，仍会抽全部，见潜在问题。
- 向导生图与设置 CG 是同一套，配完点下一步。「这次要不要先生成」收进折叠。单次回忆按 1 次或 2 次说明，自动留忆会做第二次生成。设置里有 1 到 5 次重试。
- 抽签间隔和「只在最新角色楼生成」在自动留忆卡片上。插件顶端有倒计时。楼层壳在消息内部，避免 TT 停掉虚拟化。
- 没有新编号时，倒计时旁有说明，并可以点「补」再调用一次。补上新编号后才会抽签。
- 楼层入口是爱心信。点开先看到成就句，再在这封信里打开这一轮回忆。抽中后也可以直接在信里打开该模块。失败时信上可以重试。
- 正文停稳后才挂信、才建档。摘要没点名的楼附上完整正文，不再把前面几楼截短。回到当时对准聊天上印出的楼号。成就句用模型写下的标题，标题记在计划快照外面。群聊不跑。
- 0.99.31 到 0.99.45 的自动留忆更新说明已合并。0.99.39 那句旧顺序不再单独出现。

## 潜在问题

- **没排除就会进池。** 向导默认全选。取消勾选才会排除。旧计划如果只写了偏好、排除名单仍是空的，到点仍会抽所有未排除模块；在向导里重新保存一次勾选后，取消的项才会真正不抽。
- **摘要没写楼号时，这一窗正文会整段再送一次。** 摘要点了名的楼不再附正文。摘要记录里没有楼号时，没法知道缺了哪几楼，这一窗正文会完整附上，费用会比只送摘要更高。
- **没勾选最新角色楼时，摘要路径仍可能带上增量正文。** 没强制替换窗口时，导入器原有的「基线之后的新消息」还在。摘要和这段新正文可能一起送出，费用不是严格的一次摘要。
- **没有新编号就停。** 摘要或正文送进去了，但合并后没有新的 `Mxxx`（重复、空抽取、或自动建档被未完成的私人终端草稿挡住），这一轮不抽签、不生成。倒计时进入下一个间隔，旁边会说明，并可以点「补」再问一次。模型仍认为没有可补的经历时，不再发请求，倒计时留在下一间隔。
- **第一次生成不是零请求。** 没生成过且增量数量为 0 的模块，会先做一次目录步骤，而不是直接跳过。目录长不出来才放开这张票据。
- **两个页面。** 网页锁优先。没有网页锁才用 IndexedDB 租约，有效约 20 秒，约 8 秒续一次，绑定 `chatId`、`dueFloor`、`archiveRevision`。两种锁都没有时，只靠本页的进行中标记，挡不住另一个标签页。
- **接管只跳过「全部步骤都已完成」。** 做到一半时，接管会接着原来的票据，不会新抽一张。若完成状态还没写入 metadata，接管仍可能把这一窗再送去建档。
- **楼层编号。** 「回到当时」用档案记忆上的 `messageStart` / `messageEnd`，并要求落在覆盖范围内。模型写了覆盖范围外的楼层会被丢掉。覆盖范围还是空的旧档，会相信记忆上的楼层号。按钮上印的是聊天里的 `#`，也就是 mesid。
- **群聊不支持。** 打开群聊不会自动留忆，每个群提示一次。楼层上不挂信，也不当成生成失败。一张卡里的多人物仍走原来的世界书人选。
- **正文要停稳。** 流式开始、流式 token、生成中标记、停止按钮、消息上的 streaming 类，或正文还是省略号，都不会开跑。token 停住、正文也不再是占位之后，才按间隔建档。宿主若完全不发这些事件，又把占位正文换成完整正文却不通知页面，要等下一次聊天事件才会接着跑。
