# 心迹回廊：整体逻辑

日期：2026-09-22  
对象：当前仓库 `tokimemo`（显示名心迹回廊，内部名 Heartbeat Memories，现行 `0.98 / r84.44`）  
这是一张**运行地图**。需求合同在 `Heartbeat-Memories-Project-CURRENT.md`，已做和未做在 `施工方案.md`。

---

## 1. 它是什么

SillyTavern 第三方扩展。用户**主动**把当前聊天整理成一份独立档案，再从这份档案长出相簿、ADV、房间、终端等玩法。

它不替代主聊天，不改酒馆楼层正文，也不把模型输出写回角色卡。主聊天仍是 ST 的；本插件只读聊天 / 角色卡 / 世界书，写出自己的档案和派生内容。

一句话回路：

```
当前聊天（+ 可选世界书 / 外部摘要）
        ↓ 用户点「建档」
正式档案 memoryBank（Mxxx，最多 240 条）
        ↓ 用户点某个玩法
派生内容（相簿 / 房间 / ADV …）
        ↓ 校验通过才写入该聊天的缓存
下次打开同一聊天，读缓存，不自动再请求模型
```

---

## 2. 两层启动

普通进酒馆**不加载**完整逻辑，避免 2000 楼聊天一打开就解压大缓存、扫世界书、开 IndexedDB。

| 层 | 文件 | 做什么 |
|---|---|---|
| Bootstrap | `index.js` | 菜单、轻量诊断、自动同步楼数门槛。不解压档案缓存。 |
| Runtime | `dist/heartbeatMemories.bundle.js` ← `src/heartbeatMemories.js` | 用户打开档案室 / 完整设置，或自动同步真正到期时才 `import`。 |

关掉扩展会 `destroyMemoryTheater()`：加生命周期代数，让旧任务的迟到写回全部作废。

---

## 3. 作用域：一聊天一世界线

一切绑定在 **角色槽位 + 头像 + chatId** 上。复制聊天、换卡、换 Persona，都是另一条世界线。

任务开始时拍一份 `origin`（`captureTaskOrigin`）：角色、聊天、档案版本 `archiveRevision`、各模式写入栅栏。之后任何写回都要和这份 origin 对上。切去别的聊天可以让请求在后台跑完，但结果只能写回**原聊天、原档案版本**；对不上就丢进延迟队列或拒绝，绝不写到新窗口。

删除档案会留「删除栅栏」，阻止迟到结果把已删数据救活。

---

## 4. 三层资料（所有玩法共用）

生成和校验都按这三层，不能混：

| 层 | 含义 | 必须有什么 | 不能干什么 |
|---|---|---|---|
| **记忆** | 两人确实经历过 | 档案里的 `sourceMemoryIds` + 锚点原文 | 用角色卡/世界书冒充共同往事 |
| **设定** | 卡或世界书写明的身份、住处、外貌 | 逐字可引用的短句 | 把设定写成「我们已经一起做过」 |
| **推演** | 按人设合理补生活 | 无锚点；界面标成推演 | 提赠礼、同居史、用户已来访等共同经历 |

房间物件的 `basis=记忆|设定|推演` 就是这三层。相簿/ADV/成就偏记忆；日常一格/四季/蝴蝶外延偏推演，但也不能反写 Mxxx。

---

## 5. 数据存在哪

同一聊天里有几份互不替代的存储。混在一起就会把「档案满了」和「快照太大」听成同一件事。

```
SillyTavern 当前聊天
├── chatMetadata.heartbeatMemoriesArchiveV3     正式档案（Mxxx）
├── chatMetadata.heartbeatMemoriesTheaterV3     派生缓存（gzip，相簿/房间/终端…）
│
本插件自己的 IndexedDB（普通启动不打开）
├── 来源账本     建档扫到的原始片段，比 240 条大得多
├── 建档草稿     分批整理的未完成任务（先保存再请求模型）
├── 模块恢复 journal  相簿/房间等分段草稿，给「续写」用
├── 独立备份     源聊天暂时读不到时的只读副本
└── 手动 API Key 本机 AES-GCM，设置里只有不透明引用
```

正式档案 schema 为 3，**最多 240 条**记忆。多出来的合法结果进「待入档」，可导出，不算完成、不编号、不能当 Mxxx 被其它模块引用。

派生缓存按 UTF-8 **12MB** 封顶；超了保留上一份有效缓存，不截半份当完整。

来源账本另有 8000 条 / 800 万字符上限，只服务建档，不直接进每次房间请求。

---

## 6. 来源：四条路，不是一个开关

建档材料来自四条独立通路：

1. **当前聊天正文** — 按楼号范围；隐藏楼是否计入由选项决定，隐藏不重编号。
2. **手选世界书当历史** — 用户勾的书/条目，标成历史摘要后进账本，再抽成记忆。不是关键词自动激活。
3. **自动外部摘要** — 仅公开接口：千千结、柏宝书等。接口没有或未就绪是「0 条/未加载」，不是「数据库空了」。
4. **自动激活的世界书背景** — dry-run 给建档/房间当世界观，**不能单凭扫到就升级成 Mxxx**。

另外：角色卡、Persona 只做人设，不是共同历史。

界面上的「扫描记忆 / 选择记忆世界书」走 2+3；房间生成时的设定勾选更接近 4 的手选版。勾选不会关掉角色卡和 dry-run。同一来源正文现在只发送一次，不再和人物快照各送一份全文。

## 7. 建档怎么跑

入口在「当前档案」，不在内容页。用户点生成/增量/简介，而不是打开页面就收费。

```
选来源、范围、标签
    → 完整快照已选材料（不先截成首批假装完成）
    → 按每批最多 256 片段 / 24 万字符切开
    → 先把任务输入存进本机草稿，才允许第一段模型请求
    → 每段：拼 Prompt →（建档预算）→ 请求 → JSON 校验 → CAS 写入检查点
    → 失败停后续段，成功段保留，不自动重试
    → 接近 240 条：能装的进正式档案，装不下进待入档，游标停住
```

要点：

- **保存先于请求。** 存不上就发模型，刷新会丢已付费结果。
- 建档输入预算与房间等派生任务不是同一套：建档在模型容量未知时，不再用写死 32k token 拒绝。
- 增量更新保留旧 Mxxx 编号，不为 UI 改版重做全库。
- 来源或正文被改过（指纹变了）会停不安全增量；要打乱重来只能用户明确完整重建。

简介（档案标题/概述）是另一条短任务，共用恢复和身份规则。

## 8. 派生内容怎么跑（相簿、房间、ADV…）

统一入口 `generateMode(mode)`：

```
capture origin（角色/聊天/档案版本）
    → 登记逻辑任务（同模式不能并行两份）
    → 读取正式档案；没有档案则多数模式直接拒绝
    → 创建或续接 recovery journal（把当时的卡、档案、设定冻进 contentSnapshot）
    → 拼 Prompt：信封（卡+人设+世界书）+ 模式模板 + 档案切片
    → assertPromptBudget（派生任务：默认 6 万 token，字符顶跟这次预算走）
    → 独立副 API 请求（不跟主聊天模型）
    → 领域校验（锚点、结构、禁用词、外貌枚举…）
    → CAS 写入该模式 session；版本变了则延期，回到原窗口再写
    → 成功则清掉本轮 journal；失败保留 journal 供「继续未完成」
```

续写约定：已通过校验的段不重做、不重付费；只请求未完成槽。角色/聊天/来源/配置真变了就阻断，不拿新背景污染旧任务。

多人卡：用户勾选人物名单，冻进 `participantSnapshot`。房间/相簿按名单生成；名单外的人不应进结果。同一世界书来源正文只发送一次，人物提示只带短资料和来源键。

## 9. 一次请求里实际有什么

以「他的房间」为例（其它受控模式同类）：

```
【受控信封】CHARACTER_CARD_JSON + USER_PERSONA_JSON + WORLD_INFO_TEXT
【模式合同】短任务说明、编号规则，文末要求只输出一个 JSON。各页字数下限仍在
【档案切片】最多约 24 条记忆的 id/标题/700 字摘要/锚点
【可选】CONTROLLED_WORLD_PRESENTATION_JSON
【多人卡】UNTRUSTED_SELECTED_PARTICIPANTS_JSON（含 sourceRefs 正文）
```

WORLD_INFO_TEXT 现在是两层相加：dry-run 扫亮的条目 + 用户手选设定（整条装进资料袋，装不下整条丢弃）。本地再拦一次 token。默认输入预算是 6 万，不是早先写死的 3.2 万。中文大约 1 字接近 1 token，看着不多仍可能超预算。

模型必须吐严格 JSON。插件当不信任数据：转义进 DOM，不给 HTML/JS/URL 执行权。明信片图元是枚举白名单，不是任意 SVG。

## 10. 界面结构

主窗口三栏：**设置 / 当前档案 / 内容**。

- **设置**：副 API（Connection Manager 或手动）、最大输出、输入预算、温度、来源开关、主题、CG 渠道、创作补充词。Key 不进设置明文。
- **当前档案**：扫描、勾选世界书、建档/增量、简介、日历入口、草稿恢复。
- **内容**：各玩法卡片。先能看入口和空状态；点生成才请求。

悬浮头像打开档案室；阅读位置可记书签。历史档案默认只读，解除界面只读 ≠ 获得写权限。

`src/ui/` 是现行界面入口；`src/modes/` 里既有真正的领域逻辑（`room.js`、`album.js`），也有一批和 `ui/` 同名的历史副本。改界面必须先看 `heartbeatMemories.js` / `ui/overlay.js` 实际 import 哪一份。

## 11. 各模式在地图上的位置

都依赖正式档案，但证据松紧不同。

| 模式 | 要什么 | 性质 |
|---|---|---|
| 回忆相簿 | 真实节点 CG + 共同回忆 | 记忆 |
| ADV EVENT | 第一人称长篇，须覆盖经历/心情等 | 记忆 |
| 他的房间 | 私人空间地图，本地 SVG | 设定为主，记忆物件要锚点 |
| 物品 / 陈列柜 | 从房间收纳物深入 | 房间的子玩法 |
| 私人终端 | 世界观里的设备与 App | 设定/推演，不冒充历史聊天记录 |
| 时空回响 | 终端里的跨时番外 | 推演 |
| 邮箱 / 出行 / 明信片 | 信件与路线 | 可推演；设计数据受白名单限制 |
| 两个人的日历 | 约会、承诺、生日 | 剧情日期，不跟设备今天 |
| 人际庭园 | 世界线人物关系 | 设定条目 |
| HEART | 基础语言、四季、日常一格、萤火虫 | 人设；生日默认不强制 |
| 角色印象曲 | 歌词文本，不产音频 | 创作 |
| 蝴蝶效应 | 平行世界模拟 | 不反写 Mxxx |
| 前世今生 | 独立番外 | 不反写 Mxxx |
| ENDING / 成就 | 告白回看、解锁 | 必须真实记忆锚点 |

退役：`timeJourney`（错位相逢）入口已删，旧数据不活跃保留。

## 12. 生成渠道与费用纪律

- 使用插件自己的副 API，不偷偷跟主聊天切模型。
- 同时最多约 2 个真正打到模型的请求；逻辑主任务最多 5 个。准备、数 token、校验、保存不占 provider 名额。
- **空回会自动整段重来一次。写到一半没闭合的，会自动接着补。** 其余失败默认停段，等人点继续。「失败后自动重试未完成部分」和「第一次完成后自动进行第二次生成」都默认关。限流等待不是换模型。
- 有超时和取消。关掉档案室不强制杀掉已授权后台任务，但刷新页面不是后台服务：没落盘的在途结果会丢。
- CG 走已获准的柏宝绘公开 API；用户确认才画。失败不自动再画一张。

## 13. 校验写回（为什么失败常常「0 次请求」）

很多红字发生在**还没出网**时：

1. 身份/来源和旧草稿不一致  
2. 输入 token/字符超过本地预算  
3. 恢复快照（投影，不是整卡整库）超过约 120 万字符  
4. 正式档案已 240 条，建档拒绝再收费  
5. 本机草稿存不上（12MB / 配额 / CAS）

过了这些才会 `providerRequests ≥ 1`。回来之后还有 JSON 形态、领域规则、禁用词、外貌枚举。空回会再请求一次，截断会接着补；别的校验失败默认不自动再请求。

正式写入用 **copy-on-write + `archiveRevision` CAS**：读到的版本必须仍是当前版本。并发时保双方、报冲突，不拿旧结果盖新档案。

## 14. 源码怎么分层

```
index.js                 轻量壳
src/heartbeatMemories.js runtime 入口
src/core/                设置、身份、常量、主题、调度、诊断
src/archive/             建档、来源账本、导入批次、档案室、备份
src/generation/          请求客户端、Prompt、恢复 journal、CG
src/modes/               各玩法领域（生成+校验；部分含旧 UI 副本）
src/ui/                  现行窗口、设置、各阅读页
dist/                    打包结果，安装要用这份
```

改行为时：建档走 `archive/repository.js`；房间/相簿走 `generateMode` → 对应 `modes/*.js`；所有出网走 `generation/client.js`。不要在 UI 里另写一套请求。

## 15. 读代码时先抓住的不变量

1. 每个聊天一份档案，不串世界线。  
2. 共同往事只能来自 Mxxx，不能来自世界书扫到的句子。  
3. 未点生成不请求模型；打开页面 ≠ 付费。  
4. 先能保存，再允许发请求。  
5. 成功段单调保留，失败不重做成功段。  
6. 真换卡/换聊天/换来源就停，不猜测「应该还是同一个人」。  
7. 模型输出是数据，不是代码。  
8. 诊断和 toast 不许带 Prompt、卡正文、Key。

这八条比任何单次功能补丁都优先。修「房间超预算」或「满档不能开相簿」时，应改打包和快照投影，而不是取消这些闸。
