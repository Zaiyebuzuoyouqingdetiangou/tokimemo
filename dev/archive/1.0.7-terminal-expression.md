## 根因及实现

1. phoneEntryBasis 原先要求出现“今天／明天／计划”等词才把误标 memory 的普通应用内容归回日常，其后 normalizer 会把 title/preview/detail/fields 覆盖成摘录。现在普通非聊天应用不要求出现这些时间词，仍走现有共同历史、用户发言及私人字段核验；真实历史聊天和联系人不放宽。phoneAppPrompt 写清应用内容结构与 contactName 适用范围；联系人支持从姓名字段取真实姓名，不用页面标题冒充对象。
2. 旧摘录只在明确手动补全时请求替换，其他可读条目保留；本次失败、未返回条目、不可用替换保留原文；旧空目录能生成一项应用内容而不是无操作按钮。已有草稿时沿用生成草稿继续路径，不删除断点。
3. 账目清单展示已有字段、名帖展示姓名卡片，统一文本转义；保留已有应用详情与返回操作，不生成假余额。无内容时提供真正的生成入口；只读和备份禁用生成。
4. 表情卡拍只添加一个 direction catalog 项和本地匹配规则，旧七类定义原样保留。规则使用现有 group/diff/frames/hold，不加 JSON 字段、人物门槛、最小镜头数、素材配额或自动收费调用。类型选择不会重画旧素材。
5. MV 快捷入口位于歌曲页面上部，不受封面、长歌词和歌曲列表高度影响；两种显示模式、当前 song id 和只读／未完成条件共用原处理器。
