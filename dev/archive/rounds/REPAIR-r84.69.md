# r84.69 存储与邮箱修复

版本：0.99.17 / 0.99.17-r84.69-mail-storage。
基线：测试分支 d796a4bf264dc24f263d7ffc298ab4f3dc4fda09。
目标：按用户授权推送测试分支，保留测试分支已有文件与工作流；main 不修改。实际提交回执见交付消息。

## 本轮修复

1. 取消固定 12MB 存储字节上限及对应压缩长度门槛，未替换成另一个上限。草稿保存、重读、导入、正式检查点、独立备份及缓存压缩/解压口径一致。是否保存成功仍以实际事务及 CAS 回执为准。存储不足时停止后续模型请求、保留已有记录和本页成果；提示先导出，不再建议清除本站数据。
2. 单人卡邮箱读取本次真正发送的完整角色资料，不再先截断 JSON 导致解析失败，也不再把单字段先截到 5000 字后丢掉外貌。未扩大宿主读取范围。
3. 多人卡读取本次发送的、按人物绑定的世界书正文，不要求每个外貌摘录重复写人名。共用条目按具名段落归属；不同人物不能借用彼此外貌。
4. 单独生成、一起生成、冻结草稿恢复采用一致来源；一起生成复用已经发送的人物资料，不再追加重复正文。
5. 新信未获得合格的模型小画时，从明确来源中识别已有外貌、从本信识别可绘场景进行本地补绘，不调用模型。不使用陌生人的资料或凭空默认人物；没有明确来源、无法判定多人归属或没有支持的场景时，仍可能留白。旧信、旧图按已保存快照显示，不批量补画。
6. 包含前轮 r84.68 的草稿去重、成功分段先入档、续跑不重复请求、覆盖范围和并发保护修复。

邮箱插画合同只调整本项需要的人设/世界书来源说明和有依据时提供小画的要求。其他模块创作 Prompt 未改动。结构化枚举、本地 SVG 安全渲染、人名归属、CAS、删除栅栏、身份隔离、备份和轻量启动保持。没有修改其他数量、单批规划或模型输入预算；取消存储字节门槛不代表设备存储/内存无限。
