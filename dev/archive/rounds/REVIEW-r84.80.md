# r84.80 草稿与邮箱修复复核

版本：0.99.28 / 0.99.28-r84.80-draft-repair。

本轮按截图修复。开始时本地为 r84.59，推送前发现测试分支已更新为 r84.79（d08e3ee），因此合并最新远端并把修复迁到重构后的真实运行模块。远端房间绘制、提示词、容量政策、失败说明、小画及其他更新保留。

## 原因与修复

- 图一是插件自己的草稿状态拦截。旧代码以全局忙碌状态阻止放弃，活动标记残留也会拦住操作。现在显式放弃只停止相应任务，等待收尾后保存删除状态；存储失败则保留草稿。被撤销任务的迟到回调不能恢复或改写草稿。
- 修改同一角色的描述会改变内容指纹，旧草稿虽然列在任务中心，操作时却匹配不到。现在以角色槽位、头像、聊天及档案归属核对；冻结来源完整时继续原任务并保留原成功片段。导出和放弃不要求当前生成配置与旧配置一致。真实换角色、聊天或档案仍隔离。
- 重复点击只合并同一项正在处理的操作，按钮显示处理状态并在结束后恢复；不同聊天、模块、页面或草稿分别处理。重试从准备阶段就绑定草稿身份，放弃 A 不会取消正在准备的 B。
- 编辑角色卡后旧邮箱可能被误判为另一人；新逻辑用稳定身份及当前档案的原邮箱记录核对。新信继续追加，收藏等操作不重新生成。已知本地错误显示具体原因；历史记录未留下的原因无法凭空恢复。
- HTML 错误表示模型服务/代理返回了网页，不是正常 API 响应。插件保留已完成部分并支持处理连接问题后重试，不能让上游服务故障自动消失。
- 删除档案室总列表重复的“两个人的日历”卡片；内容页的日历、其他入口和原数据保留。
- 本轮没有新增生成次数、字数、保存容量、每日请求数或重试间隔限制，也未恢复远端已移除的来信往事出处校验。
