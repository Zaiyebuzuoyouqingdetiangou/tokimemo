# 1.0.4 / r84.221 导入图片与段落撤销

基线：已交付 r84.220 ZIP，SHA-256 为 23cb355ef380db1d5bf14ef0820ef0b1e9444dcf92f7a7c537866480b3878eff。

## 根因与修复

剪辑台导入和单镜重画将图片写入 shot.image；v2 读取缩略图、画面和完成状态时却优先查 group.diff.image，忽略已保存的 shot.image。现在有单镜图时使用单镜完整画面，否则沿用共享构图；共享素材和同组其他镜头不变。导出预加载采用同样的实际图片来源，恢复构图按钮仅清除所选镜头引用，不删除旧文件。

旧手动导入复用固定文件键，异步写入失败时仍立即更新引用。现在每次使用新键，等待文件事务成功，捕获原目标再通过现有保存 journal 提交。新 frameEdit 指纹包含分镜修订与原镜头；换聊天、换歌或改分镜不会把迟到图片写错位置，连续导入只提交最近选择。

撤销栈原来只保存 taps；撤销总把目标清成 -1。全部段落有时间时 findIndex 返回 -1，大按钮被禁用；乱序打点则退到别的未点段落。现在撤销记录同时保存操作段落，恢复时间后重新选中它。顺序打点、邻接时间边界、音频和逐句打点规则保持原样。

## 验证入口

原有回归文件保持原字节。本环境 Node 子进程测试只给文件级结果，因此 run-media-sync-suite.py 为每个测试文件独立起进程，进程内用 --test-isolation=none，保留完整逐项 TAP，再汇总结果。原始断言、失败预期和业务代码没有为此放宽。
